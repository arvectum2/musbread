# CP-51D — очередь редакторских задач по версии

16 октября 2026 · закупка №0372200172326000015 · доконтрактный прототип. **Ни выполненная задача, ни внутреннее замечание не означают утверждения материала музеем или разрешения на публикацию.**

## Реализовано

- В закрытом журнале замечаний появилась **очередь задач** со статусами «Открыта», «В работе», «Выполнена внутри команды», приоритетами (высокий/обычный/низкий), ответственным и ссылкой на изменённый материал. Открытые задачи выше выполненных, внутри списка — по приоритету и ключу.
- Для каждого изменённого материала/события/раздела доступна форма постановки либо обновления задачи; ответственный, приоритет, статус и обязательный комментарий (3–1200 символов) сохраняются **новой записью**, не стирая предыдущие. Историю всех назначений и результатов можно развернуть прямо в карточке. Нет автоматической отправки уведомлений или фонового выполнения.
- Все действия строго связаны с SHA-256 базового и подготовленного локального снимка CP-44D. После изменения сайта старые задачи остаются в приватной БД как история, но **не участвуют в очереди новой версии**. Нельзя изменить задачу устаревшей формой: ответ `409` до записи. Без проверенной локальной базы страница закрыта.
- Задачу может открыть **superuser** на любом изменённом объекте. Администратор может назначить ответственным себя либо редактора, который имеет действующий прямой grant на **текущий раздел** материала. На глобальные события/структуру назначение только superuser — их отдельные ACL не согласованы. Редактор с grant может завести задачу на себя для собственного материала или обновить существующую задачу, **если она назначена ему**. Редактор не может «забрать» чужую задачу, назначить другого пользователя, читать чужой раздел либо обойти отзыв доступа. Переназначение выполняет администратор.
- Сервер повторно сверяет права на текущий раздел, группу/ключ изменённого объекта, статус, приоритет, ответственного, оба SHA-256 и CSRF. Имя исполнителя и комментарии HTML-экранируются. Очередь использует те же ACL-ограниченные группы, что и журнал CP-49D; история чужих задач не доступна. Заголовки `no-store`, `noindex` и CSP прежние.
- Приватная миграция `museum_editorial_task_updates` хранит добавляемые события: `baseline_sha256`, `candidate_sha256`, `item_group`, `item_key`, `task_status`, `priority`, `assignee_id`, `actor_id`, `note`, `created_at`. Ни один флаг не меняет `museum:verify-review`, `museum:preflight` или экспорт, не создаёт задач за пределами локального прототипа.

## Проверки

- `MuseumPublicationDiffTest`: администратор назначает редактора и переносит задачу между состояниями с сохранением всей истории, редактор сам ведёт только свою задачу, не может захватить чужую, изменить чужой раздел/событие, указать неуполномоченного исполнителя; отзыв grant запрещает GET/POST, старая версия блокируется, XSS экранируется, неверные значения/гость не принимаются.
- Isolated `scripts/qa_cms_browser.py`: в существующей авторизованной Playwright-сессии CMS ставится задача на редактируемую новость, задаются высокий приоритет и состояние «В работе», проверяются сводка и история. Затем подтверждается корректная сборка публичной статики без черновиков.
- Полный PHPUnit, 12 тестов архива/отката, 27 публичных browser E2E и GitHub Actions. Без нового платного ПО, без изменения TinyMCE, **0 ₽**.
