# MusBread — комплект передачи, структура и контроль

Текущий ZIP — только **предконтрактная демонстрация**, не акт приёмки. Создать и проверить:

    python3 scripts/handoff_bundle.py build --output /tmp/musbread_preaward.zip
    python3 scripts/handoff_bundle.py verify /tmp/musbread_preaward.zip

Содержимое source/ собирается **из Git HEAD** с фиксированной версии, а не из незафиксированных файлов. Не включает vendor, node_modules, .env, реальные базы, секреты или рабочие бинарные сборки. Служебные файлы:
- README_FIRST.md — прямо обозначает статус «не приёмка»;
- MANIFEST.json — git SHA, размеры и хеши исходных файлов;
- SHA256SUMS — контрольные суммы всех элементов пакета (кроме самого файла сумм);
- INVENTORY.csv — опись с отметкой «права не проверены»;
- STATUS.json — не изготовленные форматы и не подключённые сервисы.

**Статус обязательных типов исходников**: AI, EPS, SVG, PSD, TIFF, PPT, PPTX — готовых утверждённых дизайн-исходников нет. Есть PDF/HTML-каркасы трёх концепций по пять страниц; это не заменяет редактируемых итоговых материалов.

## План итоговой структуры, пока не сформирован

- 01-source-code: код и инструкции без секретов
- 02-brand: утверждённые RU/EN логотипы, AI/EPS/SVG, лицензии, брендбук
- 03-digital: цифровые макеты и экспорт сайта
- 04-print-museum: билеты, указатели, этикетки, афиши, сувениры
- 05-presentations: настоящие редактируемые PPT/PPTX для 4:3 и 16:9
- 06-docs: инструкции, лицензии, отчёты и акты
- 07-evidence: UX, QA, разрешённый пентест, подписанные протоколы
- SHA256SUMS: реальные суммы всех переданных файлов

Не переименовывать SVG в AI или PDF в PPTX. Файл с нужным расширением НЕ означает, что он редактируется корректно.

## Контроль на стороне заказчика после завершения разработки

1. Сопоставить акт с реальной версией исходников, номером контракта и Git SHA.
2. Проверить контрольные суммы архива, распаковки и копий с HDD/Яндекс.Диска.
3. Открыть и отредактировать хотя бы по одному файлу каждого обязательного формата в поддерживаемом приложении.
4. Проверить лицензионные уведомления, выбранную айдентику и акты права.
5. Получить реальные доступы отдельно по защищённому каналу либо перевыпустить их.
6. Зафиксировать дату, получателя, носитель и подписи; сохранить доказательства независимо от HDD.

## Статус CP-28D

Для внутреннего контроля использовать scripts/audit_delivery_readiness.py. VISITOR_GUIDE_DRAFT.md готов только в виде черновика, финальная инструкция требует утверждённых сервисов и скриншотов музея. SHA архивов и наличие исходников не являются подтверждением переданных прав или подписанного акта.

## CP-29D — атомарная сдача фирменного стиля

Каноническая опись DESIGN_DELIVERABLES.csv — 113 позиций, статус утверждённых результатов 0. При изготовлении всех носителей проверять по ID соответствующий исходник, приемочный размер/формат, редактируемость, лицензии, 300 dpi в натуральном размере, затем заносить в DESIGN_EVIDENCE.csv и сверять файл отдельно на HDD и закрытом Яндекс.Диске. Бинарная сигнатура не подтверждает право передачи или работу в Illustrator/Photoshop/PowerPoint. Фактическая физическая сдача и подписание пока не проводились.
