### 1. Общая архитектура сайта

Для реализации требований пункта 2.2.3.4 Описания объекта закупки выбрана двухконтурная архитектура, предусматривающая разделение системы управления содержимым сайта и публичной пользовательской части.

**Закрытый контур (контур управления)** предназначен для размещения системы управления содержимым (CMS), базы данных, административного интерфейса и механизмов подготовки публикаций. Доступ к нему предусматривается только для уполномоченных сотрудников с использованием установленных Заказчиком доверенных IP-адресов и иных согласованных средств защиты.

**Публичный контур** предназначен для размещения и предоставления посетителям готовых статических страниц сайта. Публичный сервер не содержит административной панели, базы данных CMS и иных компонентов, предназначенных для непосредственного управления содержимым сайта.

Указанный подход обеспечивает разграничение доступа, снижение рисков несанкционированного воздействия на CMS и независимую работу публичной части сайта.

### 2. Выбранные программные технологии

Для реализации предусмотренных Описанием объекта закупки функций предлагается следующий технологический стек:

- **Laravel и MoonShine** — система управления содержимым сайта, редакторскими ролями, материалами и процессами публикации;
- **PHP-FPM версии 8.4 или выше** — среда выполнения серверной части CMS;
- **реляционная СУБД** — хранение управляемого содержимого, настроек и необходимых служебных данных в закрытом контуре;
- **HTML5, CSS3, Sass (SCSS), JavaScript** — технологии реализации пользовательского интерфейса;
- **Next.js** — инструмент формирования статических HTML-страниц и ресурсов публичной части сайта;
- **Nginx** — веб-сервер для предоставления статического содержимого и выполнения необходимых функций обратного прокси;
- **systemd** — управление серверными фоновыми процессами и заданиями публикации.

Использование Next.js предусматривается **на стадии сборки статического содержимого**. Для обычного просмотра публичного сайта не требуется постоянное подключение к CMS или выполнение серверного приложения Next.js на публичном веб-сервере.

Таким образом, выбранный способ формирования страниц сохраняет предусмотренную техническим заданием модель публичного контура, работающего со статическим содержимым в режиме «только для чтения».

### 3. Механизм обновления содержимого

Предусматривается следующий порядок публикации материалов:

1. Уполномоченный сотрудник создаёт или изменяет материал в CMS.
2. После выполнения предусмотренных процедур проверки и одобрения система формирует пакет данных для публичной части сайта.
3. Передаваемые файлы проходят проверку целостности с использованием контрольных сумм SHA-256.
4. Подготовленная версия сайта передаётся в публичный контур по защищённому внутреннему каналу и становится доступной посетителям.
5. Предусматриваются версионирование публикаций и возможность возврата к предыдущей работоспособной версии.

Архитектурой предусмотрена автоматизация публикации по расписанию либо по соответствующей команде уполномоченного сотрудника.

Решение проектируется с учётом требования пункта 2.2.3.5 о публикации одобренных изменений не позднее 60 минут.

### 4. Информационная безопасность

При проектировании учтены требования пунктов 2.2.3.3 и 2.2.3.4 Описания объекта закупки.

Предусмотрены изоляция административного и публичного контуров; ограничение доступа к закрытым компонентам системы; использование HTTPS/TLS версии не ниже 1.2; исключение прямого публичного доступа к CMS и базе данных; контроль целостности передаваемых материалов; журналирование операций управления и публикации; возможность восстановления предыдущих версий опубликованного сайта.

Окончательная настройка сетевого разграничения, защищённых каналов, средств защиты и проверка их работы должны выполняться на инфраструктуре, предоставляемой Заказчиком.

### 5. Выполненные предварительные работы и испытания

Исполнителем разработан работоспособный архитектурный прототип и проведены предварительные функциональные испытания в собственной виртуализированной тестовой среде на базе Docker.

В ходе испытаний проверены изоляция закрытого и публичного контуров; создание и одобрение тестовых материалов в системе управления; подготовка данных и статических страниц для публикации; передача подготовленного содержимого в публичный контур; проверка целостности передаваемых файлов; предоставление опубликованных тестовых страниц через Nginx; блокировка публикации изменённых или не прошедших проверку файлов; механизм возврата к предыдущей опубликованной версии.

**Предварительные испытания подтвердили работоспособность основных архитектурных механизмов в тестовой среде Исполнителя.**
