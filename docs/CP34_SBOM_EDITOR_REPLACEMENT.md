## 3. Два режима редактора сейчас

| Режим | Настройка | Возможности | Цена и риски |
|---|---|---|---|
| TinyMCE (сохранён как default) | MUSEUM_ENTRY_BODY_EDITOR=tinymce | Текущий visual WYSIWYG: заголовки, жирный/курсив, списки, ссылки, undo/redo, русский интерфейс | Встроенный редактор GPL-2.0-or-later, юридический вопрос до передачи |
| Native HTML-source fallback | MUSEUM_ENTRY_BODY_EDITOR=html-source | Редактирование и сохранение ограниченного HTML в стандартном MoonShine Textarea, без подключения TinyMCE JavaScript на конкретной странице | Нет визуальных кнопок WYSIWYG; требует знания HTML; всё ещё установлен GPL-пакет, поэтому не является юридически финальной заменой |

В обоих режимах серверная нормализация/санитизация HTML, role-based access, черновики, опубликованность, экспорт и статическая безопасность должны оставаться неизменными. Новая настройка **не переключается автоматически в production**, никто не должен объявлять альтернативу функционально равнозначной без UX-проверки. Для изменения config/cache перед развёртыванием требуется безопасный технический релиз, а не ручная правка живого продакшена.

## 4. Вариант полноценного визуального редактора без GPL TinyMCE

Выбирать и включать только после проверки оригинальной лицензии и решения заказчика. Технические кандидаты: самостоятельный MIT/BSD-допустимый редактор на ProseMirror/TipTap или Quill. Эти названия — кандидаты для последующего лицензионного и функционального сравнения, не одобрение и не заявление, что конкретные текущие версии/плагины свободны от ограничений.

Порядок:
1. Зафиксировать базовые функции редактора в реальном MoonShine: H2/H3, параграф, bold/italic, списки, внутренние/внешние ссылки, вставка, undo/redo, русская локализация, доступность клавиатурой/VoiceOver, изображения с ограничениями.
2. Выбрать один проверенный источник с открытым текстом лицензии, версионными ограничениями и полностью локальной поставкой без CDN/подписок. Отдельно проверить плагины и transitive пакеты.
3. Добавить в CMS интеграционное поле с сохранением того же body HTML и серверным HTMLPurifier; сделать round-trip с существующими записями и миграционный возврат к черновику без потери текста.
4. Проверить XSS, javascript: URL, вставку iframe/script, загрузку файлов по ролям, CSP, offline-режим и возможность редактировать уже сохранённые материалы. Не расширять whitelist HTMLPurifier без тестов.
5. Протестировать в реальном браузере редактора 2–3 типовых сценария, клавиатуру, масштаб 200%, доступность, вставку русских текстов. Заказчик должен подтвердить UX и отсутствие потерь редактирования.
6. После согласования убрать moonshine/tinymce из composer.json, пересобрать composer.lock/vendor/public assets, убрать загрузку GPL JavaScript, обновить SBOM/NOTICES и тесты. До удаления библиотеки нельзя писать «GPL исключён».
7. Проверить на чистом deploy/reinstall: отсутствие редактора в composer.lock, vendor/public, публичных static exports, нет сетевых CDN, нет секретов, воспроизводимый downgrade/rollback.
8. Сделать правовой review стороннего кода и согласовать исключение чужих библиотек из передаваемых прав. Подготовить лицензионные уведомления вместе с официальной сдачей.

**Граница ответственности:** выбираем локальную бесплатную интеграцию по правам и качеству; само принятие правового риска GPL и итоговый функционал согласуются после контракта. Текущий status по 113 дизайн-носителям 0 утверждено, расходы 0 ₽, Docker не нужен.
