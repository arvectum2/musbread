# Реальные испытания WebKit и клавиатуры: TZ-111/207/208/210/238/240

18.10.2026, закупка 0372200172326000015. Исходное ТЗ, стр. 163, 252–253, 281–283. Все изменения в проекте на внешнем ArvectumSSD на Mac mini.

## Обнаруженный и исправленный дефект

Первый полный прогон Playwright WebKit: **174 прошли, 3 упали на реальном управлении клавиатурой**. При нажатии Tab движок WebKit, использующий настройки macOS по умолчанию, пропускал ссылки без явного атрибута tabindex, включая «Перейти к содержимому», «Все подразделы» и документы музея. Дефект не проявлялся в Chromium.

Изолированный браузерный эксперимент подтвердил: явный tabindex=0 на ссылках восстанавливает нативное последовательное перемещение Tab и Shift+Tab. Поправлены три компонента: MuseumLink (внутренние ссылки), MuseumAnchor (внешние/сквозные), RichText (санитизированные оригинальные HTML-тексты музея). На любом href проставляется стандартный tabindex=0, заданный программно отрицательный tabindex авторского компонента не перезаписывается. CMS не может пронести свой вредоносный положительный tabindex в HTML. Никакого JS-перехвата клавиш, фокус-ловушки или изменения браузерных/системных настроек macOS.

Результат: **185/185 полного Playwright WebKit**, включая ранее падавшие три проверки, отдельные проверки исходных музейных ссылок и 48 случаев адаптивного расположения на 8 реальных страницах при ширинах 1280, 768, 640, 480, 390 и 320 CSS px. Эти проверки НЕ выдают изменение viewport за нативный Page Zoom. У Chromium до изменения также существовали 90 настоящих аппаратных Chrome Page Zoom проверок через API расширений, результаты сохранены отдельно. Повторная полная браузерная регрессия Chromium также прошла: 185/185, включая проверку 48 responsive reflow случаев на восьми реальных страницах и новую последовательность Tab в оригинальном музейном архиве документов.

Проверка готового статического HTML на пяти категориях: все **932** реальных ссылок в выборке имеют tabindex=0 (главная 185, документы 211, билеты 184, контакты 178, поиск 174). Реальный WebKit тест подтверждает переход с первой ссылки реестра оригинальных музейных документов на вторую через Tab с видимым контуром фокуса.

Регрессия закреплена в существующем CI-скрипте scripts/audit_static_navigation.py: теперь он проверяет tabindex=0 **на каждой** внутренней и внешней ссылке в собранных HTML, в том числе на ссылках на PDF музея. Полная проверка: **81 HTML-файл и 12 488 проверенных внутренних переходов**, ошибок нет. Добавлены отрицательные Python-тесты для href без tabindex и href с tabindex=-1; временные тесты Firefox и диагностические страницы не входят в коммит.

## Firefox: воспроизведённый блокер

Playwright Firefox был скачан строго в закрытую папку .local_archive на внешнем SSD, без установки браузера в системные Applications. Запуск на macOS в headless с временным профилем по умолчанию и со специально созданным внешним TMPDIR возвращает одну и ту же ошибку Mozilla: Could not find profile folder. **Firefox не считается протестированным**. После окончания проверки загрузку можно удалить с SSD. Не подменять Firefox браузером Chromium или WebKit и не менять системные настройки без отдельной необходимости.

## Честный светофор

- TZ-111 остаётся жёлтым: тест WebKit недостаточен, чтобы подтвердить последние две версии native Safari, Firefox, Edge и Yandex.
- TZ-207 остаётся жёлтым: расширено реальное покрытие клавиатуры на двух движках, но полноценный UAT вспомогательных технологий с финальной билетной системой и формами ещё требуется.
- TZ-208 и TZ-210 остаются зелёными: нативные Tab, Shift+Tab и кольцо фокуса доказаны на двух движках для исходных музейных текстов и навигации.
- TZ-238 и TZ-240 остаются жёлтыми: responsive reflow 48 новых измерений не равен Page Zoom native Safari/Firefox/Edge/Yandex; реальные Chrome 100–200% проверены отдельно.
- TZ-259 остаётся жёлтым: все требуемые браузерные бренды, включая Chromium-GOST/Atom/Opera, ещё не доступны на испытательном стенде.
