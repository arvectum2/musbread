# CP-TZ241-03 — контроль лишних запросов и честный замер через Nginx

**Дата испытаний:** 19 октября 2026 года. **Связь с ТЗ:** TZ-241 / пункт 2.2.3.8.1 — загрузка до трёх секунд на большинстве устройств. **Площадка:** Mac mini, оригинальная сохранённая сборка на ArvectumSSD, Chrome headless, изолированный localhost Nginx (Docker).

## Что изменено

В общую внутреннюю навигацию MuseumLink добавлен режим prefetch=false по умолчанию. Следовательно, многочисленные исторические ссылки на архивные новости и каталоги не генерируют опережающие запросы Next.js RSC при простом открытии страницы. На настоящий клик переход не влияет. Если где-то потребуется опережающая загрузка, компонент может явно задать prefetch=true.

Добавлен новый браузерный тест apps/web/e2e/tz241-speculative-prefetch.spec.ts: три страницы без фоновых RSC fetch, рабочий клик по новости и интерактивный поиск.

Доработан существующий лабораторный скрипт apps/web/scripts/qa-performance.mjs: по умолчанию он по-прежнему поднимает локальный Python HTTP-сервер без сжатия; дополнительный третий аргумент позволяет использовать **только** URL с буквальным IPv4 127.0.0.1 и HTTP, чтобы проводить те же замеры через уже запущенный Nginx. Сеть заказчика и внешний Интернет для тестирования запрещены.

## Фактические HTTP-запросы Chromium

Профиль 390×844 CSS px, холодная страница, сбор сетевых ответов до load плюс 500 мс:

| Маршрут | Запросы до изменения | Запросы после | Ненужные fetch до | Ненужные fetch после |
|---|---:|---:|---:|---:|
| Новости | 24 | 11 | 10 | **0** |
| Музей | 23 | 12 | 10 | **0** |
| Поиск | 26 | 10 | 13 | **0** |

Ссылка на новость от 16.10.2026 проверена настоящим кликом: переход с архива на отдельный материал с заголовком выполняется корректно.

## Замедленный мобильный Chromium: полноценный load, p75

Во всех испытаниях 390×844, новые холодные браузерные контексты, CPU slowdown 4×, сеть 150 мс RTT / 1,6 Мбит/с, 3 повтора на каждый URL. p75 по трём повторам равен худшему из трёх — это лабораторный ориентир, **не полевая статистика посетителей**.

| URL | Python HTTP без сжатия, после оптимизации, мс | Настоящий Nginx с gzip, мс | Nginx FCP p75, мс | Nginx LCP p75, мс |
|---|---:|---:|---:|---:|
| Главная | 4000 | **1421** | 656 | 656 |
| Новости | 8841 | **1809** | 632 | 632 |
| Музей | 4675 | **1511** | 636 | 636 |
| Поиск | 3906 | **1419** | 620 | 620 |

В Nginx реально получены HTTP 200, Content-Encoding: gzip и Vary: Accept-Encoding. Контейнер запускается только с привязкой порта к 127.0.0.1 и удаляется после испытаний.

**Интерпретация:** отключение speculative prefetch подтвердило уменьшение фоновых запросов, **но** почти не снизило p75 полного load на несжимающем Python-сервере. Ускорение в Nginx связано в первую очередь с отличающимся способом HTTP-обслуживания, включая gzip, в комбинации с оптимизированными материалами предыдущего этапа CP-TZ241-02. Нельзя приписывать всё сокращение времени только prefetch=false.

Реальный локальный Nginx во всех четырёх сценариях показал p75 load **меньше 3 секунд**. Это доказательство работоспособности инженерного решения на стенде, но ещё **НЕ** доказательство исполнения требования «на большинстве устройств» в конечной среде музея.
