# TZ-154 — публичный архив прошедших мероприятий

16 октября 2026 · исходное ТЗ, пункт **2.2.3.6.1**, строка **207** первичного `tz.txt`; матрица `TZ-154`, приоритет P1. **Не** дополнительные фильтры задач CP-52D.

## Что уже готово в доконтрактном прототипе

- В публичной афише `/events/` есть доступные с клавиатуры три режима: «Предстоящие», «Архив», «Все», со счётчиками, сообщением для пустой выборки и сортировкой. Предстоящие — по ближайшей дате начала; прошедшие — от новых к старым. События в день начала/окончания ещё считаются актуальными.
- **Прошедшие события не удаляются из опубликованного snapshot:** сохраняются детали `/events/{slug}/`, ссылки и sitemap; в шапке и описании нет утверждений о реальном расписании (пока используются только демонстрационные данные). Главная показывает ближайшие события, не выдавая прошлогоднюю афишу за актуальную.
- Реальное отличие от даты сборки SSG: после загрузки React сортировка использует **календарный день посетителя**, обновляется при возвращении во вкладку и регулярно во время открытого просмотра. Серверный первоначальный HTML использует день сборки для избежания несовпадения гидратации; при отключённом JavaScript состояние может устаревать без повторной публикации, что нужно учитывать в последующем UAT.
- В приватную CMS MoonShine добавлена необязательная **дата окончания** для многодневных мероприятий (`ends_at`), с валидацией конца не ранее начала, строгой проверкой preflight и выгрузкой `ends_on` в публичный snapshot. Если дата окончания отсутствует, событие трактуется как однодневное. Многодневное событие уходит в архив **после дня окончания**, а не после начала. Статусы `draft` / scheduled по-прежнему не экспортируются.
- Поддержаны обычные PHP-экспорт/дифф, предпросмотр публичных страниц, доступность переключателей, локальные и CI-тесты. Ни TinyMCE, ни внешние службы не меняются.

## Чего **нет** (поэтому матрица — `Частично`, а не `Да`)

Не загружены реальные прошлые мероприятия музея, не подтверждены даты и длительность программ, отсутствуют предоставленные заказчиком права на фото/текст и официальная приёмка архива. Требуется интервью/контент музея и проверка сценариев завершения многодневных выставок. Тесты используют фиктивные даты ноября 2026 и явную маркировку демонстрационной версии.

## Проверки

- `npm run test:events`: прошлое/сегодня/будущее, порядок выдачи, неверные/неполные даты, многодневные мероприятия, неизменность исходного массива, локальный календарный день.
- `apps/web/e2e/site.spec.ts` с принудительной тестовой датой: сохранение страниц прошлых событий, переключатели, домашняя афиша без прошедшего, граница смены дня (архивировать после даты окончания). Клавиатурное нажатие Enter сохраняет корректность с виртуальным временем Playwright.
- `MuseumExportTest`: диапазон дат в публичном snapshot, без черновиков; `MuseumEventAndLinkPreflightTest`: некорректный конец раньше начала блокируется в `--strict`; общий PHPUnit, статические ссылки, CMS e2e и GitHub CI.

После подписания контракта: загрузить настоящее расписание и архив музея и уточнить, нужны ли времени/часу начала и завершения более точные статусы.

**Обратная совместимость (проверена CI fixture):** поле `ends_on` добавляется в JSON **только при указанной дате окончания**. Старые однодневные события сохраняют прежние byte-for-byte JSON и SHA-256: чистая база + `DemoMuseumContentSeeder` дала ровно `5fdbebaf569d5ba884819cc0669962cb5864c82146e3cd5afd07d582f9ceaf2e`, совпадает с `apps/web/src/data/published.json`. Это предотвращает неожиданный провал сравнения эталонных снимков и повторную публикацию не менявшихся данных.
