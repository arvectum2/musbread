# MusBread · проверка первоисточников перед переносом разделов

**17 октября 2026.** Перед изменениями проверены первичное ТЗ (сводный реестр из 325 строк), публичные разделы самого Музея хлеба (прямой доступ Mac mini), а также организационные примеры [Музея истории Санкт-Петербурга](https://www.spbmuseum.ru/themuseum/contacts/54092/) и [Русского музея](https://rusmuseum.ru/pages/the-charter-of-the-museum/). Копирование чужих правовых документов и биографий исключено.

## Выполнено

1. **TZ-310 и TZ-312 (раздел 4 ТЗ, строки 374–379):** исправлен opt-in импорт существующей структуры CMS. Семь верхнеуровневых разделов, прямо предусмотренных ТЗ, и дочерние разделы с реальной ссылкой на старый сайт отображаются; **24 неподтверждённых дочерних раздела ТЗ теперь сохраняются как черновики**. Это не удаляет заготовки, не затрагивает уже созданные редактором разделы и не выдаёт им права публикации. Подтверждение дерева и реальные права доступа музея остаются открытыми.
2. **TZ-134 (2.2.3.6.1), TZ-184 (2.2.3.6.3):** в каталоге официальных документов 5 групп, **19 ссылок на настоящие ресурсы музея**: 15 файлов PDF/DOCX и 4 тематические официальные страницы. Правовые тексты не составляются и не изменяются. При сверке HTML обнаружена ранее добавленная ссылка на PDF «Правила посещения музея»: файл отдавался по прямому адресу, но отсутствовал в исходном официальном разделе. Ссылку убрали; добавили действующие пункты, буквально указанные в разделе «Цены и условия предоставления услуг».
3. **Существующий раздел администрации:** вместо пустой страницы — пять должностей с официально опубликованными ФИО и рабочими телефонами; ФИО из устаревшей копии поискового индекса, отсутствующее на живой странице, сознательно исключено. Нет выдуманных фото, биографий, личной почты или данных.
4. **Контроль источников:** скрипт scripts/audit_existing_museum_site.py запускается на Mac mini по запросу и проверяет ссылки в справочной карте разделов и каталоге, MIME для документов, наличие ссылок непосредственно в живых HTML-разделах, а также наличие пяти ФИО на странице администрации. Последний отчёт [MUSEUM_SOURCE_LINK_AUDIT.json](MUSEUM_SOURCE_LINK_AUDIT.json) — **46/46 URL HTTP 200**, все 15 файлов представлены в соответствующих исходных разделах, 5/5 ФИО найдены. Периодический сетевой отказ одного PDF при первом прогоне снят повторным контролем по IPv4. Никаких новых юридических документов не изготовлено.

## Воспроизводимость

- Проверка актуальной привязки источников: из корня проекта запустить python3 scripts/audit_existing_museum_site.py --output docs/tz-audit/MUSEUM_SOURCE_LINK_AUDIT.json.
- Проверка модели и изоляции черновиков: cd apps/cms && php artisan test --filter=MuseumSectionExportTest.
- Проверка каталога и данных на фронтенде: cd apps/web && node --experimental-strip-types --test src/data/museum-team.test.ts src/data/museum-official-documents.test.ts.
- Браузер: cd apps/web && npx playwright test e2e/museum-team-source.spec.ts e2e/tz-museum-official-documents.spec.ts.
- Проверка production-статического вывода: cd apps/web && npm run build.

## Что заказчик должен подтвердить до реальной публикации

- Утверждённое дерево разделов и условия публикации новых блоков из ТЗ.
- Актуальные редакции документов, возможность размещения файлов на новом сервере или постоянную ссылку на старый сайт.
- Должности, ФИО и служебные телефоны администрации.
- Права на тексты, визуальные материалы, корректность английского перевода; UX и визуальный стиль после интервью.
- Конкретные роли и гранты сотрудников в CMS, защищённую сеть и изоляцию production-контуров.

**Этот протокол не равен приёмке заказчиком и не изменяет световую оценку до закрытия всех условий первичного ТЗ.** Системный диск Mac mini не использовался для исходников, логов или отчётов; работа шла на /Volumes/ArvectumSSD/arvectum/repos/musbread.
