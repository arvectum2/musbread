# CP-41D — редакторский список материалов: поиск, фильтры, доступные связи

16 октября 2026 · №0372200172326000015 · **CP-41D — внутренний доконтрактный чекпоинт**, не контрактный CP-41 (не утверждение фирменного стиля и не приёмка). Изменения не трогают TinyMCE и не публикуют музейный контент.

## Функциональность

В уже существующем MoonShine-ресурсе «Материалы музея» (`/admin/resource/museum-entry-resource/museum-entry-index-page`):

- Поиск по названию, H1 и slug (штатный механизм MoonShine без стороннего поискового движка). Поиск не требует id-LIKE и остаётся переносимым между SQLite и PostgreSQL.
- Фильтры по типу (новость, страница, экскурсия, выставка, документ), редакционному статусу (`draft/published`) и разделу сайта. Список допустимых разделов строится по текущим правам пользователя; только superuser может найти публикации «Без раздела».
- Отдельный фильтр **«Готовность к экспорту»**: черновик; ожидает срока; скрыто неопубликованным разделом или предком; готово к следующей выгрузке. Это обзор *состояния по данным БД*, а не доказательство, что изменённая версия уже развёрнута на публичном сервере. Готовность повторяет правило `museum:export`: статус `published`, дата не позже текущей, опубликованы все предки раздела; для legacy-записей без раздела прежнее поведение экспорта сохраняется.
- Фильтр **«Наличие связей»**: «Есть связи» и «Нет связей». Для редактора учитываются только связанные материалы в разрешённых ему разделах; событие афиши учитывается в пределах текущих полномочий CMS. Наличие связей с чужой веткой не выдаёт редактору её имя или отдельное число.
- В списке появились отображаемое название раздела, дата запланированной публикации, счётчик **доступных** связанных материалов и событий. Прежние действия «Настроить связи» и «Открыть предпросмотр» сохранены. Для заголовка/даты доступна штатная сортировка MoonShine.

## Безопасность и тесты

- Фильтры применяются к базовому запросу, уже ограниченному `MuseumEntry::editableBy($user)` (только назначенные ветки). Самостоятельная установка URL `filter[museum_section_id]` на чужой ID не отменяет ACL, а недопустимые состояния фильтра возвращают пустую выборку.
- Все SQL-предикаты с параметрами и проверенными идентификаторами; не используется вывод пользовательского HTML как разметки; никакие черновики не покидают закрытую CMS в публичный JSON.
- `MuseumEditorialListFiltersTest`: тесты реального HTTP MoonShine, поиск, фильтры по всем четырём редакционным состояниям, разрешённые разделы/чужие ID, отсутствие передачи связей другого раздела, статус «Без раздела», пограничные значения и доступность исходных вариантов списка.
- `apps/web/cms-e2e/editor.spec.ts`: реальный браузер проходит поиск, фильтры «готово/черновик», «есть/нет связей», «без раздела», видит предпросмотр и счётчики; тесты выполняются в изолированном контуре `scripts/qa_cms_browser.py` и завершаются построением публичного Next.js из реальных CMS-записей.

## Ограничения

- Экран является **рабочим редакторским обзором**, не утверждённой заказчиком аналитикой. Реальные разделы и роли музея нуждаются в согласовании после итогов закупки.
- Статус «готово к экспорту» не равен уже выложенной версии: реальный релиз осуществляется отдельным защищённым pipeline CMS → JSON/SHA256 → Next.js → release/rollback.
- Приватные права по событиям афиши остаются более грубыми, чем по материалам (у событий пока нет собственного разделового ACL); уточнение после интервью.
- Количество связей показывает редакционно доступные связи, а не только уже вышедшие публично. Для публичного сайта CP-39D по-прежнему фильтрует draft и закрытые ветки.
- TinyMCE **без изменений**, сторонних сервисов и расходов нет: **0 ₽**. Это не контрактная сдача.
