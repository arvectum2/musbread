# CP-36D — контроль production-only установки закрытой CMS на Linux

Дата: 16.10.2026. Предконтрактная подготовка №0372200172326000015. **Не поставка на оборудование музея и не правовая экспертиза.**

## Изменения

- У `scripts/audit_built_artifacts.py --mode cms` появился строгий аргумент `--composer-profile production` (старый профиль `all` сохранён для CI с PHPUnit и локальной разработки).
- Production-профиль требует, чтобы фактический `vendor/composer/installed.json` **в точности** соответствовал `packages` из Composer lock, без единой `packages-dev`. Проверяются реальные каталоги, точные версии, симлинки и SHA-256 содержимого всех пакетов, а также опубликованные ресурсы MoonShine/TinyMCE.
- В GitHub Actions отдельная Linux Ubuntu / PHP 8.4 job запускает `composer install --no-dev`, проверяет загрузку маршрутов закрытой CMS, публикует локальные админ-ассеты и сохраняет независимый JSON-аудит с хешами. Это отделено от test job, где нужны инструменты разработки.
- Негативные тесты: объявление dev-пакетов в production, наличие лишнего dev-пакета даже при ложном флаге `dev=false`, отсутствие обязательного production-пакета, неизвестный режим.
- Результат работы аудитора **не содержит чужие исходники и пользовательские данные**. На GitHub хранится только временный CI-артефакт на 7 дней, а не ложный универсальный образ production-бинарников.

## Граница проверки

- Проверяется Linux-окружение **GitHub Actions**, не конечная ОС, PHP-FPM, Nginx, сертификаты, ACL и IP-сегментация музея.
- Даже при валидном production-профиле `moonshine/tinymce` и его GPL-2.0-or-later JS остаются в поставке: `tiny_mce_removal_status=STILL_INSTALLED`.
- Пять Gilroy WOFF2 и транзитивные скомпилированные JS/CSS MoonShine сохраняют риск неподтверждённой передачи прав. В отчёте нет заявления о «чистой лицензии».
- Это **не** runtime-пентест, проверка функциональной равнозначности WYSIWYG или согласование музеем.

## Воспроизведение

В чистом Linux workspace выполнить `composer install --no-dev` в `apps/cms`, запустить `php artisan vendor:publish --tag=laravel-assets --force`, затем из корня репозитория:

```sh
python3 scripts/audit_built_artifacts.py --mode cms --composer-profile production --out /tmp/musbread-cp36-cms-production.json
```

В CI дополнительно выполняется проверка `php artisan route:list --path=admin` и assertions по ключевым счётчикам. Финальный результат — зелёная job и сохранённый `musbread-cp36-linux-production-cms-files`, а не утверждение результатов музеем.
