# CODE-AUDIT-06 — гонки при скачивании, CSRF и разделение прав редакторов

**20.10.2026.** Разработка только на Mac mini, внешний ArvectumSSD, локальная ветка MusBread. Без push, без обращения к продуктивному CMS и серверу muzei-xleb.ru, без изменения музейных материалов, без отправки новых вопросов заказчику.

## Исправление: проверка одного файла и чтение другого

**Было:** в MuseumDocumentController::download проверялись SHA-256 и размер исходного файла в закрытом хранилище; дальше Symfony BinaryFileResponse получал его *путь*, повторно открываемый позднее при формировании HTTP-ответа. При замене/редактировании файла между проверкой и чтением существовала теоретическая гонка.

**Стало:** контроллер с проверкой разрешения редактора читает один ограниченный (не больше установленного inspector MAX_BYTES = 15 MiB) байтовый снимок документа и сравнивает его фактический размер и SHA-256 со значениями БД. Неправильное значение/исчезновение файла/symlink приводят к 404. Новый MuseumDocumentInspector::verifyBytes проверяет структуру именно этих байтов с помощью временного файла в закрытом Laravel storage/framework, который обязательно удаляется через finally. HTTP-ответ содержит те же, уже проверенные байты. Контракт скачать как attachment с application/octet-stream, nosniff, sandbox CSP и Cache-Control private/no-store сохранён.

**Тест:** MuseumDocumentsTest проверяет скачивание правильных байтов, последующую подмену источника после формирования ответа, отказ при повреждении/замене той же длины и symlink, отсутствие остаточного файла инспектора. Выдача ограничена памятью до 15 MiB на одновременный ответ; для большого параллелизма после договора потребуются отдельные нагрузочные тесты. Не утверждаем абсолютную физическую атомарность записи на диск.

## Реальная CSRF-проверка с production gate

Обычный Laravel PHPUnit выполняется при APP_ENV=testing и обходит CSRF. Новый MuseumCsrfCriticalRoutesTest временно переводит *только тестовую среду* в production для выполнения middleware PreventRequestForgery и потом обязательно возвращает прежнее состояние. В шести POST и четырёх PATCH/DELETE действиях (загрузка, альт-текст, редакторское одобрение/очередь, заметки, удаление, HTML-редакция) поддельный токен вместе с Sec-Fetch-Site=cross-site вызывает HTTP 419, а валидный токен позволяет разрешённую подсказку alt. Ни публикаций, ни отправки оригинальных файлов не происходило.

## Проверка разделения прав редакторов

Новый MuseumDocumentSectionBoundaryTest: редактор, которому назначен один раздел, не может просматривать, удалять, менять отметку доступности или согласовать HTML-эквивалентность документа *чужого* раздела (403). Редактор может успешно согласовать описание доступности своего документа; чужая запись остаётся неизменной. Ранее существующие тесты безопасности медиатеки и ролей сохранены.
