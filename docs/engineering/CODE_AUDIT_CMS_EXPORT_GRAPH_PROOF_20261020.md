# CODE-AUDIT-15 — независимая сверка связей и обложек в приватном proof

**20.10.2026 / MusBread / Mac mini / ArvectumSSD.** Продолжение CODE-AUDIT-14, без изменения оригинальных материалов музея, действующего сайта, DNS, очереди customer production, публичной схемы Next.js и приватных прав MoonShine. Нет push и деплоя.

## Основание и найденный риск

CODE-AUDIT-14 уже создаёт в закрытой БД пообъектный proof «одобрение → конкретная строка snapshot → SHA-256 snapshot/manifest» после выполнения реального queued exporter. Проверяет обязательные поля, вложения, версии и manifest. Однако сам CODE-AUDIT-14 честно указывал: отношение related_entries / related_events и event cover не проверялись независимой реконструкцией. Подмена этих полей с пересчитанным атакующим JSON/manifest могла получить ложный proof, хотя не менялся действительный approval.

## Внесённые дополнения (только verifier и тесты)

1. MuseumExportContentVerifier независимо собирает из CMS **тот же разрешённый список опубликованных entry/event IDs** с учётом сроков и видимости разделов/родителей и сверяет с содержимым связанных списков внутри **реально записанного** snapshot JSON.
2. Для каждой entry заново строятся related_entries и related_events: отфильтрованы скрытые/непубликованные targets, сортировка по title + ID повторяет контракт сериализатора, проверены тип, заголовок и настоящий публичный href. Для event аналогично сверяются related_entries.
3. Для события отдельно заново вычисляется cover_image. Допускается только media опубликованной записи из того же раздела, без незакрытых ограничений на права, с валидным SHA-256. Сверяются src, alt, width/height, caption, заполненный long_description. Сам исходный WebP должен существовать и проходить прежние проверки manifest по SHA-256 и размеру.
4. Введены допустимые **списки ключей экспортированных entry/event/section**, запрет лишних/приватных полей. В strict approval mode на верхнем уровне разрешены только schema_version, фиксированная до согласования museum site-заглушка, collections entries/events/sections. Неодобренные дополнительные поля, списки персональных контактов и изменённые статические надписи приводят к отказу даже после пересчёта общего manifest.
5. Бинарный manifest, схема публичных URL и JSON, внутренняя запись approval, CAS и очередь не изменялись. Не расширены права обычных редакторов. Новые проверки — **fail-closed до подтверждения proof**: при расхождении не добавляются новые строки пообъектного свидетельства и запуск завершится ошибкой через существующий PublishMuseumSnapshot.

## Испытания

- Новая positive fixture: две реально одобренные новости и одно одобренное событие, связанные в одном снимке. Верификатор подтверждает **3** записи content proof.
- Реально сгенерированный WebP из тестового GD, привязанный к одобренной новости и выбранный обложкой одобренного события, проходит сверку. После изменения alt внутри фактического JSON и **пересчёта** JSON/manifest — отказ.
- Negative-проверки отдельно изменяют related_entries у новости, related_events у новости, related_entries у события, добавляют неизвестное поле со служебным email, а также меняют фиксированное описание проекта. Каждая подмена происходит в исходном JSON с пересчитанным новым manifest SHA-256; verifier отказывает. Отклонённые попытки не создают proof rows.
- Узкие тесты verifier + живого queued экспортного сценария: **19 PASS, 125 assertions**. Полный Laravel **405/405 PASS, 4146 assertions**, Python **360/360 PASS**. Проверки PHP lint и git diff --check PASS.

## Границы

Это подтверждение согласованности **конкретного приватного snapshot** с действующим approval и выбранными CMS projections при проверке, не независимый архив и не свидетельство публикации на muzei-xleb.ru. В будущем нужны неизменяемая копия исходного snapshot/manifest/asset bytes, проверка после доставки и переключения реального release, права заказчика, HTTPS, наблюдение результата и сроки 60 минут. Значение подписанного approval и SHA-256 пакета остаётся привязанным к этому локальному моменту; изменения CMS позже не меняют историческое свидетельство.

Реконструкция одобренных полей дополнена, но не является альтернативной реализацией *всей* верстки сайта, политик отображения и всех возможных доп. полей. Для тех изменений нужен отдельный тест.
