# CODE-AUDIT-14 — криптографически привязанный к выгрузке приватный реестр объектов

**20.10.2026 / Mac mini / ArvectumSSD.** Изолированная инженерная задача MusBread: доказать, какие редакционно одобренные записи действительно включены в конкретный закрытый пакет, а не полагаться лишь на успешный код выхода фонового задания. Не изменялись действующий muzei-xleb.ru, DNS, публичная индексация, музейная БД, права пользователей или форматы данных Next.js. Ни push, ни боевого деплоя.

## Дефект, обнаруженный аудитом

До этого этапа приватный MoonShine-журнал связывал одобрение с запуском по publication_run_id и отображал статус succeeded, однако **не доказывал включение именно данной редакции** в фактический generated published.json. Несколько approvals могут объединяться в одну очередь; обновление статьи после одобрения делает эту связь особенно неоднозначной. Существующий snapshot-manifest.json защищал общий файл и медиаресурсы по SHA-256, но не хранил приватной пообъектной привязки approval → exported row.

## Реализовано

1. Новая PG/SQLite-совместимая миграция **2026_10_20_160000_create_museum_export_content_proofs.php**: в museum_publication_runs добавлены nullable content_verified_at, content_proof_count, manifest_sha256. Новая приватная таблица museum_export_content_proofs хранит publication_run_id, approval_id, subject_kind, subject_id, revision_sha256, snapshot_sha256 и export_record_sha256 с уникальностью одного subject на один run. Старые run остаются без proof — **не помечаются подтверждёнными ретроактивно**. Никаких признаков доказательств внутри public schema_version=1.
2. MuseumExportContentVerifier запускается **из реального queue:work после успешно завершённого museum:export и проверки общего SHA-256**, но до отметки run=succeeded; **только в opt-in museum.editorial_approval_queue**. Он считывает фактические байты published.json и manifest, проверяет общий digest/размер, schema_version=1, counts, однозначные ключи, полноту множеств экспортированных published CMS entries/events/sections, отсутствие лишних/дублированных/отсутствующих записей, действующую queued-approval точного SHA-256. Подтверждает основные поля, в том числе тело, заголовки, даты, SEO, переводы, медиа/документы (alt/caption/accessibility), видеометаданные; собранные ссылки на WebP/PDF/DOCX/XLSX должны соответствовать реально существующим файлам и значениям SHA-256/bytes манифеста. Для каждой экспортированной строки фиксирует SHA-256 канонического JSON по существующему MuseumSnapshotSerializer и SHA-256 конкретного общего snapshot. Сверка записей и фиксация доказательств выполняются локально. Ошибка не записывает частичных доказательств; очередь помечает задачу failed.
3. Идентичности из snapshot связаны с защищённой CMS через type+slug (entries), slug (events/sections), без экспорта служебных ID. Неоднозначные identity — отказ. SHA одобрения вычисляется из **актуальной** CMS модели и её зависимостей, как требует уже существующий MuseumApprovalRevision. Новые разрешения на одобрение не вводились.
4. При повторном запуске ранее упавшего задания прежние proof rows и метки удаляются **до нового экспорта**, транзакционно с переводом запуска в running. Если opt-in выключен (старый предконтрактный режим), экспорт по-прежнему совместим, но **не получает** content_verified_at, count или proof. Завершённые задания остаются idempotent.
5. MuseumPublicationJourneyStatus и страница приватного журнала показывают **фактический проверенный запуск**, число объектов, SHA-256 манифеста и SHA-256 экспортированной строки. Связь ищется по ID approval среди **успешных verified runs**, а не только по original publication_run_id (потому что запросы могут coalesce в более позднюю выгрузку). Старое одобрение другой редакции не превращается автоматически в новое. Без доказательства UI пишет «Не подтверждено для связанного запуска». Название старого MoonShine ресурса уточнено: «Запуски закрытой выгрузки».

## Границы доказательства

- **Это приватная запись о содержимом пакета в момент проверки.** SHA экспортированной строки и общего файла сохраняются как свидетельство конкретных байтов; последующие записи CMS или перезапись staging не меняют исторический hash, но для независимой повторной проверки архива через месяцы необходимо также хранить **неизменённую копию исходных файлов**. Такой архив с политикой хранения ещё не внедрялся.
- Верификатор сравнивает идентичности, наборы объектов, выбранные поля основной записи, метаданные файлов, видео и переводы; не формирует независимо всю сериализованную модель из всех связей и опциональных полей (например related_entries/related_events). Он не подменяет безопасность существующего экспортера и approval gate. Наличие SHA строки означает подтверждение именно прочитанных байтов, а не сторонний аудит редакторской смысловой корректности.
- Сторонние публикационные системы, production webroot, HTTPS, DNS, репликация, контент, реально отображаемый посетителю на muzei-xleb.ru, и SLA 60 минут **не проверены** и данным реестром **не подтверждаются**.
- Реестр доступен только администратору в прежней закрытой CMS (никаких прав редакторам), в публичном JSON нет actor_id, approval_id или внутренних идентификаторов. Синтетические тестовые изображения/материалы не относятся к фактическим материалам музея.
- Договорный светофор ТЗ **325: 85 готово / 118 частично / 122 не готово** не изменяется автоматически от внутреннего QA.
