20.10.2026. Предконтрактный прототип, ArvectumSSD / Mac mini. Живой музей, DNS, SEO, документы, дизайн и права не менялись. Работа ведётся локально, без push.

### Исправление R1 — hydration формы

Причина: useEffect немедленно вызывал setHydrated, нарушая react-hooks/set-state-in-effect; из-за этого общий ESLint падал.

Устранено через useSyncExternalStore и разные server/client snapshots: сервер и отсутствие JS возвращают false (fieldset disabled); после React hydration — true. Не добавлено ни POST на публичный сервер, ни передача ПДн в закрытую CMS. Реальные браузерные тесты в том числе без JS проходят.

### Исправление R2 — логика раздела guide

Динамическая страница guide/[slug] исходно 308 строк и смешивала JSX, фильтрацию источников и редакторские решения. Вынесены чистые функции в apps/web/src/data/guide-page-rules.ts: удаление дублей официальных каталогов и повторной ссылки на текущую CMS-страницу, выбор официального текста с приоритетом редакторской публикации. 5 unit-тестов проверяют условия. Ни названия экспонатов, ни оригинальные музейные тексты, ни URL не изменялись. Для пяти календарных блоков применяется один buildDay внутри рендеринга.

Следующий этап — аккуратная декомпозиция большого JSX без изменения HTML, только с отдельными маршрутными проверками.

### Исправление R3 — воспроизводимость документов и очереди

Две причины падения полного Python-набора: неактуальный вопрос TZ-112, хотя по первичному реестру пункт уже готов, и ручные комментарии в сгенерированном TZ_EXECUTION_MATRIX.md, которые стирались при регенерации.

Теперь CUSTOMER_RFI_QUEUE.csv пересобран строго из OPEN_CUSTOMER_QUESTIONS.csv / requirements.psv: 240 открытых пунктов, 240 НЕОТПРАВЛЕННЫХ записей, ни одного нового вопроса. Четыре исторических примечания перенесены в TZ_EXECUTION_MATRIX_CHECKPOINTS.md. Генератор читает этот источник и включает записи в итоговый Markdown детерминированно. Тест воспроизводимости и тест соответствия всех 325 строк снова проходят. Новые checkpoint-записи нужно вносить только в отдельный источник, не вручную в генерируемый Markdown.

## Проверка готового сайта после рефакторинга

Полная сборка museum-deploy PASS: 945 HTML-страниц, 101 исходный PDF/DOCX без потери SHA-256, 259 оригинальных музейных фото URL / 255 локальных WebP, 27 старых страниц пагинации, 280 оригинальных новостей. 0 новых необъяснённых битых ссылок. 22 вхождения трёх уже неисправных URL исходного музея остались прежними.

Буквальные SHA многих HTML-файлов изменились вследствие пересборки и замены имён скомпилированных JS-ассетов Next.js. Сохранность контента доказывается маршрутными инвариантами и браузерными проверками; побайтовое равенство всех страниц НЕ заявляется.
