# CODE-AUDIT-12 — мобильный UX, клавиатура, WCAG и понятность редакторских действий

**20.10.2026 / Mac mini / ArvectumSSD.** Только закрытая MusBread CMS и одноразовая тестовая SQLite, без live muzei-xleb.ru, без изменения официальных материалов музея, индексации, DNS, постоянной базы и внешних пользователей. Git push и деплой не выполнялись. Звук Mac mini не менялся.

## Исходное измерение: что действительно мешало

Автоматический Playwright + axe-core аудит настоящих страниц CMS под синтетическим авторизованным редактором: Chromium/WebKit, ширина 320/390/768 пикселей, пять маршрутов редакторской формы, изображений, документов, предпросмотра и preflight = **30 комбинаций**.

Первый прогон:
- 5 комбинаций с ненулевой общей CSS scrollWidth, 4 из них из-за широкого списка документов (35–105 пикселей при 320/390); пятая из-за закрытого off-canvas меню WebKit при ширине 320.
- Страница MoonShine: 5 типов axe-core нарушений — aria-input-field-name у трёх TomSelect, button-name у кнопок меню/поиска, link-name у иконок действий, color-contrast в хлебных крошках, meta-viewport с user-scalable=no.
- Медиатека, документы, предварительная проверка и предпросмотр **уже не показывали** axe-core нарушений. Это был дефект встроенного стороннего MoonShine UI, не весь проект.

## Исправленные проблемы

1. **Мобильный список документов.** В docs/index.blade.php добавлен корректный box-sizing border-box и адаптивное обрамление таблицы с локальной горизонтальной прокруткой, tabindex=0, role=region, aria-label и читаемой клавиатурной инструкцией. Теперь таблица прокручивается САМА, не выталкивая весь документ за границы окна. Сохранены штатные формы проверки доступности и управления документами, без переконвертации исходных PDF.
2. **Доступное масштабирование MoonShine.** Создан локальный override Blade head, из viewport удалено maximum-scale=1.0/user-scalable=no. Исходники установленных пакетов Composer не трогались. Файл внутри resources/views/vendor явно включён в репозиторий несмотря на широкий gitignore vendor/.
3. **Две кнопки раскрытия бокового меню.** Локальный override MoonShine burger задаёт видимое скринридеру aria-label и динамическое aria-expanded; браузерный Enter открывает и закрывает меню.
4. **Подписи динамических элементов MoonShine.** Лёгкий JavaScript museum-cms-accessibility.js через официальный MoonShine assets API именует TomSelect combobox по смыслу исходных селекторов type/section/status, а также кнопки поиска и иконки просмотра/удаления. Использует MutationObserver с объединением изменений в один animation frame, без сетевых запросов и замены обработчиков событий. Этот компенсационный слой следует сверять с будущими версиями MoonShine.
5. **Цвет и фокус.** Локальный CSS-пакет убирает недостаточную прозрачность хлебных крошек, делает их читаемыми на светлой палитре и предотвращает горизонтальную прокрутку закрытого меню на самом узком экране WebKit. Правила не применяются к тёмной теме без проверки её цветов.
6. **Предпросмотр.** Из сохранённой записи добавлены прямые клавиатурно доступные ссылки «Вернуться к редактированию материала», «Проверить изображения», «Проверить документы», «Проверить готовность к закрытой выгрузке». Явно пояснено, что предпросмотр ничего не публикует.
7. **Формулировки.** На preflight техническая кнопка больше не обещает разместить сайт; называется «Сформировать закрытый пакет (не публикует сайт)». При конфликте редактирования описание двух колонок не опирается на «слева/справа», поскольку на мобильном они идут друг под другом.
8. **Ошибки загрузки.** В MuseumMediaController и MuseumDocumentController стандартные частые ошибки выбора материала, alt, названия и размера файла локализованы на русский с конкретным следующим действием. В случае ошибки загрузка по-прежнему не создаёт файл и возвращает в контекст исходного материала.

## Итог браузерной проверки

Для воспроизводимости добавлены scripts/qa_cms_editorial_browser_audit.mjs (Playwright + axe-core) и scripts/qa_cms_local_ux_browser.py (отдельный сервер Laravel на 127.0.0.1 с одноразовой базой/админом и данными на ArvectumSSD). Этот вариант был необходим, когда Docker Desktop Mac mini временно перестал отвечать; его не запускали/не перенастраивали за счёт работающих проектов. В scripts/qa_cms_nginx_fpm_docker.py также добавлен опциональный вызов того же browser QA, который по умолчанию теперь строго проверяет доступность, если включён MUSBREAD_QA_BROWSER_AUDIT=1. Никаких внешних серверов для QA не использовалось.

**30/30 страниц/экранов (2 движка × 3 ширины × 5 экранов):**
- **0 axe-core нарушений** по выбранным правилам WCAG 2.0/2.1 A/AA;
- **0 случаев фактической горизонтальной прокрутки всей страницы** при явной проверке window.scrollX после попытки перемещения;
- **0 сломанных клавиатурных фокус-переходов по автоматическому критерию**, Enter на мобильной кнопке меню проверен отдельно, внутренняя таблица документов имеет клавиатурно доступную область прокрутки;
- одна известная внутренняя CSS-метрика WebKit: document scrollWidth +10 пикселей на 320px экране из-за свернутой боковой панели MoonShine. На реальный horizontal pan это не повлияло. Проводить ручную приёмку самого sidebar после обновления vendor.

**Ограничения:** axe-core не заменяет ручной VoiceOver/экранный диктор на устройстве сотрудника, проверку 200%/400% реального браузерного зума, работу людей с Jodit и полную проверку тёмной темы. Эти пункты нельзя автоматически объявлять выполненными. На последнем прогоне использовался встроенный Laravel HTTP-сервер вместо недоступного Docker; Nginx/FPM интеграция была отдельно проверена ранее (CODE-AUDIT-11), но после этого UX этапа повторить её не удалось.
