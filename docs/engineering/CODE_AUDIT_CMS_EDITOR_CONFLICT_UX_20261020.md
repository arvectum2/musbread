# CODE-AUDIT-10 — безопасный UX конфликтов редакторов MoonShine

**20 октября 2026; Mac mini / ArvectumSSD.** Никаких изменений боевого сайта/домена музея, ЕИС, оригинальных музейных данных и баз заказчика. Весь контроль — отдельные тестовые базы и локальный Docker/браузер. Никакого push, деплоя или новых вопросов музею.

## Какое поведение было до изменений

Атомарная SQL-версия материалов edit_version и SHA-256 fingerprint уже предотвращали потерю изменений: второй редактор получал HTTP 409. Однако стандартная асинхронная форма MoonShine не предоставляла удобного способа посмотреть собственный несохранённый HTML рядом с новой редакцией. Без копии отправленных данных требовалось заново открыть материал и повторить ввод текста.

## Реализовано

1. Точное исключение MuseumEditConflict отдельно от других HTTP 409, с прежним кодом 409 для пустого/поддельного/stale fingerprint и CAS collision. SQL-защита и права редакторов не ослаблены.
2. Только форма материалов MuseumEntryFormPage переведена на классическую отправку вместо AJAX. Это позволяет показать полноценную страницу конфликта, а не стандартный error-toast; CRUD для других ресурсов не изменён.
3. MuseumEditConflictResponse строит HTTP 409 только после повторной проверки текущей авторизации MoonShine и допустимого раздела MuseumSectionAccess. Если доступ утрачен, содержимое новой закрытой редакции не возвращается. Данные берутся исключительно из защищённой реальной записи и текущего запроса, не по произвольному id из поля формы.
4. В ответе с локальным шаблоном edit-conflict.blade.php сравниваются 16 основных текстовых полей, даты публикации и SEO-поля в двух колонках: «Мой несохранённый вариант» и «Текущая редакция». Изменившиеся поля маркированы. Обе версии отображаются как ЭКРАНИРОВАННЫЙ текст в read-only textarea, даже если отправленный HTML содержит script-теги.
5. Сам пользователь может скачать все свои несохранённые текстовые поля как JSON или скопировать поле через clipboard (fallback: выделение текста); эти действия реализованы локальным открытым JS museum-editor-conflict.js, без обращений к API, cloud или аналитике. Есть ссылка открыть текущую редакцию в новой вкладке, чтобы исходная конфликтная страница оставалась доступна для копирования. Автоматической перезаписи/слияния нет. В базу, sessionStorage, localStorage и временные файлы сервера черновик намеренно не сохраняется.
6. Для HTTP 409 установлены Cache-Control private/no-store, noindex/noarchive, Referrer-Policy no-referrer, CSP с запретом внешних скриптов, встраивания в iframe и отправки новых форм. Есть адаптация двух колонок под мобильный экран, keyboard focus и aria-live статус копирования.
7. В Laravel local/test среде срабатывает обработчик typed conflict exception в bootstrap/app.php; при production-обработке исключений MoonShine применяется тот же рендер через modifyErrorResponse. Прочие ошибки, CSRF-отказы, 403 и любые неконфликтные 409 проходят обычную обработку.

## Проверки

- PHP feature tests: две браузерные сессии открывают одну запись, первый автор сохраняет, второй получает 409 и обе версии текста; после обновления страницы он может сохранить новую версию. Пустой/поддельный fingerprint = 409. Проверено production-исключение, XSS-экранирование пользовательского HTML и запрет утечки текущего содержимого, если раздел перевели другому редактору.
- **РЕАЛЬНЫЙ HTTP-контур:** scripts/qa_cms_nginx_fpm_docker.py создаёт Nginx→PHP-FPM→Laravel с изолированной SQLite, двумя отдельными фиктивными MoonShine-администраторами (разные cookies). Первый отправил новую версию через настоящий CSRF-защищённый POST и получил 302; второй отправил устаревший текст через другую сессию и получил **409 HTML comparison с несохранённым экранированным текстом и актуальной версией**. После второго запроса материал остался равен первой сохранённой версии. Локальный JS был доступен через HTTP. Дополнительно тот же стенд прошёл **96/96** HTTP запросов гостя и авторизованного пользователя с правильными статусами.
- **РЕАЛЬНЫЙ браузер:** scripts/qa_museum_editor_conflict_browser.mjs — headless Chromium, viewport 390x844, только синтетический HTML; проверены копирование полного исходного текста, событие download локального JSON, точность спецсимволов и отсутствие исполнения введённого HTML. Этот тест использует специально созданную DOM-фикстуру; отдельно наличие страницы в реальном HTTP проверено предыдущим тестом.

## Границы выполненного

- Черновик не синхронизируется, не переносится на второе устройство, не хранится после закрытия вкладки. Пользователь должен явно нажать «Сохранить мой черновик» или скопировать текст ДО закрытия страницы. Сохранённый на собственное устройство JSON может содержать внутренние музейные данные; обращаться с ним как с приватным файлом.
- Вместо автоматического merge пользователь вручную переносит нужные фрагменты в свежую редакцию. Это намеренная защита от перезаписи чужого содержания, а не недоработка функциональности договора.
- Статус HTTP 409 не означает, что новое содержимое музея автоматически одобрено и опубликовано. Процедура согласования остаётся прежней.
- Независимое чтение страницы экранным диктором в полном пользовательском тесте VoiceOver не подтверждено; семантическая разметка/aria-live не заменяют такую приёмку.
- Никаких гарантий по production HTTPS, инфраструктуре и доступности заказчика не заявляем.
