# CODE-AUDIT-03 — приватная подготовка и управляемое применение публикации CMS

**20.10.2026, Mac mini, ArvectumSSD.** Предконтрактный проект; никакой выгрузки на muzei-xleb.ru, деплоя, отправки жалоб/писем, изменений исходных документов или DNS. Исходная функциональность museum:export сохранена.

## Выполненная работа

Ранее команда museum:export выполняла предварительные проверки, затем напрямую создавала/удаляла публичные WebP/PDF/DOCX/XLSX и только после этого повторно проверяла, что набор редакторских одобрений не изменился. Отказ последней проверки мог оставить уже изменённые статические файлы, хотя JSON ещё не обновлялся.

Теперь:
1. После первоначального разрешения CMS создаёт уникальный staging-каталог с правами 0700 **внутри закрытого Laravel storage/app/private/museum-export-stages** на внешнем ArvectumSSD. Все изображения, документы, JSON и manifest формируются сначала только в нём.
2. Предпубликационные правила и финальный повторный контроль MuseumExplicitApprovalGate::assertUnchanged остаются обязательными. Ошибка, невалидная видеовставка, непрошедший PDF/HTML, неправильный хеш, изменённая редакция или отказ одобрения **не затрагивают целевые публичные файлы**; временная папка удаляется через finally.
3. После повторной проверки отдельный MuseumSnapshotStagedCommit валидирует точные SHA-256, размеры, список файлов манифеста, канонический JSON и пути назначения. Неизвестные имена, произвольные symlink-пути, повреждённые staged-данные блокируются **до любых изменений**.
4. Только после этого подготовленные медиа/документы атомарно заменяются **по одному файлу**. Затем применяются manifest и published.json; отозванные файлы с SHA-256-именами удаляются последними. Для каждого изменённого файла сперва создаётся проверенный rollback backup в закрытом staging.
5. Если в любом шаге случается обычная ошибка копирования, rename, удаления или искусственно вызванное исключение, журнал откатывается в обратном порядке, восстанавливая прежние файлы/manifest/snapshot. При неудаче самого восстановления бросается отдельная критическая ошибка, **не** выдаётся успешный экспорт.
6. Программа проверяет не только сам конечный путь, но и все его родительские компоненты. Произвольные символические ссылки запрещены; разрешён ровно один системный псевдоним macOS /var → /private/var для корректного размещения временных тестовых файлов.

Внешний интерфейс CLI и JSON schema_version 1, байты payload/manifest и SHA-256 сохранены; защищённая CMS, права на публикацию и состав публичных данных не менялись. Фоновая очередь дополнительно продолжает использовать закрытую staging-директорию, а итоговый локальный доставщик переключает отдельный versioned release посредством symlink.

## Граница доказанного и нерешённое

**Приватная подготовка до проверки одобрения и rollback на обычной ошибке теперь реализованы и протестированы.** Это не делает одновременную замену нескольких файлов атомарной для посетителя: при аварийном выключении питания или немедленном чтении разными клиентами между отдельными rename может возникать переходное состояние. Базовая CMS также не блокирует любое параллельное редактирование редактором после последнего gate-check: существует остаточное race-window. Для конечного боевого сайта необходимо использовать **versioned-release каталог + атомарный указатель current**, отдельные тесты power-loss/recovery и согласованный maintenance/rollback процесс. Текущий Docker-тест проверяет именно логический откат через symlink, но не физическое внезапное отключение питания.
