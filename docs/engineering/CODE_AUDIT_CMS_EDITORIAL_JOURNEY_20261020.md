# CODE-AUDIT-11 — полный навигационный путь музейного редактора

**20.10.2026.** Mac mini, ArvectumSSD, локальная ветка MusBread. Отсутствуют изменения домена, живого сайта музея, музейной БД, оригинальных файлов, уведомлений заказчику и ЕИС. Нет push/deploy. Использованы только тестовая Laravel SQLite БД, синтетические медиа/PDF и временный Docker Nginx→PHP-FPM.

## Что мешало ежедневной работе

В CMS уже существовали отдельные защищённые страницы редактирования материалов, медиатеки, документов, предпросмотра, связей и строгой предварительной проверки. Но прямой переход из открытой формы к вложениям отсутствовал. В медиатеке или документах каждый раз требовалось повторно выбирать текущий материал из всех доступных; после загрузки, изменения описания доступности или удаления возвращался общий длинный список. В списке предварительной проверки также не было ссылок на вложения конкретной записи.

## Что сделано

1. Сохранённая форма MuseumEntryFormPage теперь отображает встроенный блок «Маршрут редактора» со ссылками: изображения, документы, связи, предпросмотр новой вкладкой, проверка перед публикацией по якорю текущего материала. Явно сказано, что предпросмотр показывает последнюю сохранённую версию, а не введённые, но не сохранённые изменения. Новая ещё не сохранённая запись показывает только инструкцию сначала сохранить материал; ссылок с несуществующим ID не создаёт.
2. MuseumWorkflowEntry — небольшой общий helper двух медиатек: параметр entry в GET считывается только как контекст навигации, валидируется как положительное десятичное ID и разрешается через MuseumEntry::editableBy для данного редактора. Неавторизованный, несуществующий или неверно сформированный параметр даёт 404; авторизация редакторов и ограничения разделов неизменны.
3. Страницы /admin/museum-media?entry=N и /admin/museum-documents?entry=N выводят только файлы выбранного материала, предварительно выбирают его в форме загрузки, показывают название и предлагают ссылки обратно к форме, в соседнюю медиатеку, на предпросмотр, проверку и к общему списку. Параметр сохраняется в пагинации. Без query страницы действуют как прежде и показывают файлы доступных редактору разделов.
4. Во всех обычных успешных POST/PATCH/DELETE обеих библиотек параметр контекста сохраняется в ссылке возвращения: загрузка, обновление alt/подписей, удаление изображения, загрузка/удаление документа, изменение отметки доступности, HTML-доступная редакция документа. Если параметра не было, остаются прежние общие маршруты.
5. В списке предварительной проверки материалов появились адресные ссылки к изображениям и документам конкретного материала. Никакой доступ к чужому разделу через подмену query не предоставляется.
6. Ошибки в обычных Laravel-формах загрузки (нет alt или названия документа) возвращают на ту же страницу через referer с сохранённым контекстом и не создают запись/файл. Успешная повторная загрузка возвращает туда же. Никаких автоматических публикаций или ускоренной выдачи прав не добавлено.

## Испытания

- Новый Feature MuseumEditorialWorkflowNavigationTest: пользователь открывает материал, видит все ссылки, переходит в обе медиатеки по одному ID с заранее выбранным материалом; ошибочная загрузка не добавляет файлы и сохраняет путь; правильная загрузка WebP и PDF проходит; дальше редактирование alt/пояснения, предпросмотр, переход к preflight. Соседние материалы не примешиваются. Сотрудник другого раздела, анонимный пользователь, произвольный ID и параметр-массив не обходят ACL. Форма несохранённой записи не даёт ложных ссылок. **3 теста, 74 assertions PASS**.
- Настоящий Nginx→PHP-FPM→Laravel в одноразовом Docker стенде, две независимые MoonShine-сессии: ссылки из реальной редакторской формы существуют, обе библиотеки открываются с правильным выбранным ID, предшествующая проверка конфликтов 302→409 осталась рабочей. Дополнительно **96/96** HTTP нагрузочных запросов PASS. Это **локальный HTTP, не продакшн HTTPS**.
- Прежние критические ACL, CSRF, SVG/WebP, PDF/DOCX/XLSX, запрет несанкционированной публикации, очередь и idempotency проверяются полным Laravel-набором.
- Полный Python unittest и проверка статической поставки без изменений: **360 Python PASS**, **945 HTML, 101 музейных оригинальных PDF/DOCX по SHA-256, 259 оригинальных фото URL, ноль новых битых внутренних ссылок**. Ранее известные 22 вхождения неисправных ссылок существующего музея не изменялись.
- Все исходные PHP-файлы CMS и тесты прошли php -l. Итог полных Laravel тестов подтверждается исключительно финальным журналом .local_archive/cms-editorial-workflow-full-laravel-20261020.log.

## Что НЕ сделано этим этапом

- Не внедрялся drag-and-drop медиаподбор прямо в Jodit и не менялась библиотека редактора без требования ТЗ.
- Предпросмотр показывает только сохранённую редакцию. История редактирования и механизм разрешения конфликтов из предыдущего этапа остаются независимыми от этих ссылок.
- Наличие ссылок на проверку/одобрение не даёт обычному редактору прав утвердить публикацию; право одобрения и закрытая очередь остаются отдельным техническим контуром. Публичный деплой не выполнялся.
- Не проводились приемочные встречи сотрудников музея или VoiceOver на их рабочих местах; функциональный тест не равно доказанной удобности реальным пользователем.

Матрица всех 325 требований ТЗ **85 готово / 118 частично / 122 не готово**; эти инженерные улучшения сами по себе не меняют договорные статусы.
