# CODE-AUDIT-13 — понятный путь редакции от проверки до закрытой выгрузки

**20.10.2026 / Mac mini / ArvectumSSD.** Проверен и доработан существующий путь CMS — сохранение материала, предпросмотр, preflight, явное одобрение SHA-256, очередь и техническая подготовка приватного пакета. Нет push, деплоя, изменений DNS/индексации и живого сайта muzei-xleb.ru. Только локальные тестовые записи и одноразовая SQLite.

## Установленный UX-дефект

До работы приватный журнал показывал строку одобрения с полями dispatch_status и publication_run_id (английские системные значения). Не было понятно, завершился ли связанный запуск ошибкой, стартовал ли работник очереди, изменился ли материал после зафиксированного одобрения. Пользователь мог перепутать наличие одобрения, поставленную задачу и готовность закрытого пакета с публикацией на живом музейном домене. Список запусков в MoonShine уже существовал, но был разрознен с журналом одобрений.

## Реализовано

1. MuseumPublicationJourneyStatus — только read-only оценка последних 100 фактических редакторских одобрений. Каждая исходная редакция (материал, событие, раздел) сверяется с **текущим** SHA-256 через уже действующий MuseumApprovalRevision::forSubject, включая привязанные медиа/документы/связи. Результаты различают текущую совпадающую редакцию, изменённую редакцию, удалённую/отсутствующую запись. Исторические approved_at и SHA-256 остаются сохранёнными, ничего не переодобряется автоматически.
2. Для каждого одобрения отображаются **отдельно** факт зафиксированного решения, состояние постановки задания (pending/failed/queued) и реальный статус привязанной записи MuseumPublicationRun (queued/running/succeeded/failed/abandoned). Отсутствие связанного запуска и неизвестные статусы не трактуются как успех. Нет отображения содержимого приватных CMS-материалов в журнале, только тип/ID, хеш и статусы.
3. В закрытом журнале дополнительно отображаются последние 25 запусков с числом попыток, UTC временем, контрольной суммой **только при status=succeeded**, и безопасным типом ошибки при failed/abandoned. Статусы подробно пояснены по-русски. Неудача — сигнал диагностики, а не автоматический «повторить»: работник и защита от дублирования остаются прежними.
4. У администратора прямо на странице preflight показывается последний запуск, его реальное состояние и ссылка в подробный журнал; после постановки задачи flash-сообщение ведёт к проверке результата. Обычным редакторам статус очереди и журнал не доступны. В меню администратора добавлена ссылка «Ход закрытых выгрузок».
5. На странице сделан ясный маршрут: **сохранить → проверить → одобрить текущую редакцию → посмотреть результат приватного экспорта → отдельно подтвердить публичный релиз**. Успешный запуск строго не объявляется подтверждением, что какая-то конкретная одобренная редакция содержится в пакете: несколько запросов могут быть объединены в один запуск. Без deploy и без действий на публичном сайте.
6. Мобильная вёрстка журнала вместо широкой таблицы — структурированные секции, карточки, определения терминов, клавиатурная навигация, ссылки на конкретные запуски, без inline JavaScript и внешнего CDN. HTTP cache=no-store, robots=noindex и admin guard сохранены.

## Что этот этап не утверждает

- Нет нового функционала выкладки в production, сетевой приёмки боевого HTTPS, проверки DNS/SEO и подтверждения 60-минутного SLA публичной публикации. Реальный deployment требует отдельных внешних подтверждений заказчика и боевого окружения.
- Browser QA показал UI с **синтетическим** завершившимся неудачей заданием в локальной тестовой БД, а не фактическую работу продакшн-очереди. Переходы статусов проверены Laravel Feature-тестами. Интеграционный Nginx/PHP-FPM повторно проверен после восстановления Docker, но с **синтетическим содержимым**; публичные серверы не использовались.
- Нельзя считать факт совпадения SHA-256 и status=succeeded доказательством включения конкретной одобренной редакции в приватный пакет без независимого сравнения его manifest и содержимого. По этой причине экран прямо это поясняет.
- VoiceOver, ручная клавиатурная приёмка пользователем, 400% зум и тёмная тема остаются отдельными задачами; axe-core их не заменяет.

Матрица 325 требований ТЗ **85 готово / 118 частично / 122 не готово**: уточнение инженерных статусов не меняет договорную готовность автоматически.
