# CODE-AUDIT-16: локальный архив проверенных закрытых выпусков

Дата: 20.10.2026. Репозиторий MusBread на Mac mini / ArvectumSSD. Никаких изменений действующего muzei-xleb.ru, DNS, публичных материалов и данных заказчика, без Git push и боевого деплоя.

## Зачем

CODE-AUDIT-14/15 фиксирует отдельные SHA одобренных записей и hash фактического JSON, но очередная приватная выгрузка способна перезаписать готовые файлы в staging. Для повторного независимого аудита нужно сохранить исходные байты JSON, manifest, фото и документы.

## Реализация

- Новый компонент MuseumVerifiedExportArchive запускается исключительно ПОСЛЕ существующей строгой пообъектной проверки CMS и ДО отметки фонового задания succeeded. Режим включается только отдельной переменной MUSEUM_VERIFIED_ARCHIVE_ROOT в приватном config/museum.php. По умолчанию выключен.
- Оператор должен заранее создать приватный каталог под ArvectumSSD, вне webroot, src/ и исполняемых application folders, без symlink и с правами 0700. При неправильном каталоге архиватор отказывает.
- Под flock создаётся приватная временная директория. Копируются только файлы, перечисленные проверенным манифестом: published.json, snapshot-manifest.json, media SHA.webp, documents SHA.pdf/docx/xlsx. Верифицируются digest и размер источника и копии. Неизвестные пути, отсутствующие бинарные файлы и symlink отвергаются.
- Регистрируются точные SHA и количество байтов файлов, а также история подтверждённых content proofs: kind, identity, subject_id, approval_id, original revision SHA, exported row SHA. Receipt привязан к конкретному publication_run_id и snapshot/manifest SHA.
- После контрольной сверки staged каталог с файлами режима 0440 и папками 0500 атомарно перемещается под имя run-ID-snapshotSHA-manifestSHA. Чужой/уже существующий выпуск никогда не перезаписывается. Разные задания с одинаковым содержимым имеют разные write-once receipts.
- В БД статусов сохраняются archive_id, archive_file_count, archive_receipt_sha256 и archived_at. Существующие старые задания не объявляются архивированными. Если создание включённого архива завершается ошибкой, задание получает failed, а частичные флаги подтверждённого содержимого и proof rows данного запуска сбрасываются.
- В закрытом журнале и preflight администратор видит, архивирован ли выпуск, число файлов, ID и SHA реестра. Рядовой редактор не получает доступ к архиву.
- Новая отдельная Python-команда scripts/verify_private_snapshot_archive.py работает БЕЗ Laravel и подключения к БД. Проверяет оригинальные файлы, manifest, schema, counts, все экспортированные строки, пообъектные SHA и отсутствие подмен/неизвестных файлов. Ключевой параметр --expected-receipt-sha256 сверяет receipt с независимо записанным хешем в CMS. Без него проверяется только внутренняя самосогласованность.

## Запуск и повторная проверка

Сначала администратор настраивает отдельную приватную папку и строгую редакторскую очередь, не трогая реальные серверы музея. Для локальной независимой проверки:

python3 scripts/verify_private_snapshot_archive.py /ABSOLUTE/PATH/TO/ARCHIVE/run-ID-SHA-SHA --expected-receipt-sha256 <SHA256_FROM_PRIVATE_CMS>

Код выхода 0 означает совпадение содержимого и внешнего эталона. Код 1 означает, что архив повреждён либо содержит неучтённые данные.

## Проверка и ограничения

- Laravel архивные сценарии: 7/7 PASS, 50 assertions. Синтетическая одобренная новость + созданный в GD WebP + тестовый PDF, реальный фоновой PublishMuseumSnapshot job, receipt, запуск независимого Python offline verifier, изменение позднего staging, повторный идентичный выпуск, отказ на небезопасном каталоге и symlink, неправильные права 0755, повреждение WebP и receipt.
- Полный Laravel 412/412, 4196 assertions PASS; Python 360/360 PASS. PostgreSQL fresh migrations 47 и 8/8 реальных конкурентных сохранений PASS. Статическая поставка: 945 HTML, 101 PDF/DOCX с сохранёнными SHA-256, 259 исходных URL фотографий и ноль новых битых внутренних ссылок; 22 старых вхождения ссылок источника отмечены, а не переопределены.
- Права файлов 0440 и каталогов 0500 НЕ равнозначны аппаратному WORM: владелец с полномочиями может их поменять, удалить или изменить. Отдельный SHA реестра позволяет обнаружить подмену, но не предотвращает физическую утрату или вредоносное удаление. Отсутствуют object lock, offsite backup, договорная retention policy, защищённый timestamp/signature и реальный power-cut test.
- Реальный музейный пакет не создавался, потому что музей не оформил approvals и боевой хостинг не предоставлен. Нет доказательства публичного релиза на muzei-xleb.ru и 60-минутного production SLA.

Матрица 325 требований остаётся: зелёных 85, частично 118, не готово 122.
