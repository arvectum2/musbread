## Сделано по TZ-106

В существующую release_site.py добавлена команда чтения истории:

python3 scripts/release_site.py history --dest deploy/local

- Проверяет **каждый** сохранённый локальный каталог релиза, пересчитывает SHA-256 и ID на основе manifest; незнакомые файлы, повреждения, подмена symlink или ошибочная ссылка current/previous приводят к отказу всего отчёта.
- Показывает только ID, роль (current/previous/archived), количество файлов и объём данных. Никаких редакторских текстов, имён сотрудников, персональных данных посетителей и файлов приватного CMS-снимка в отчёте нет.
- Команда не переключает current, не чистит архив и не публикует данные. Прогон Mac mini: **10/10 проверенных локальных релизов**. Тесты охватывают обычные архивы, rollback, порчу архивного релиза, подмену указателя и симлинк в releases.
- **Не закрыто:** заказчик ещё не предоставил боевую схему хранения версий, политики хранения и реальный канал доставки.

## Сделано по TZ-094

- Сохранён CI-аудит при изменениях, а в .github/workflows/dependency-review.yml добавлена **отдельная еженедельная read-only проверка** по понедельникам 05:21 UTC с ручным workflow_dispatch. Проверяет зафиксированные версии Node prod и Composer без автоматических правок lock-файлов или деплоя.
- Проверки на Mac mini: npm audit --omit=dev — **0 advisories**, composer audit --locked — **0 advisories** на момент запуска; отчёты хранятся в игнорируемом .local_archive. Это не проверка всех dev-зависимостей и не гарантия отсутствия уязвимостей.
- Патчи ставятся только после анализа совместимости, проверки лицензий (включая TinyMCE), полного CI, согласованного окна и резервной копии/rollback. **Никакой автоматический апгрейд ядра PHP/Laravel/Next.js** в данном этапе не осуществлялся.
- **Не закрыто:** регулярность GitHub Actions нужно подтвердить после push, согласовать периодичность, обслуживание в сети заказчика и ответственных.
