# TZ-110 — отдельное одобрение редакции перед закрытой выгрузкой

Дата 17.10.2026, закупка 0372200172326000015. Исходное ТЗ: пункт 2.2.3.5, строка 162 — не более 60 минут от фактического одобрения материала редактором до его публичной видимости.

## Зачем потребовалась отдельная операция

Существующие поля status=published и published_at не являются достоверной меткой фактического решения редактора: последнее также задаёт запланированное время публикации. Фоновая выгрузка JSON и успешное завершение задания не гарантируют появления страницы на публичном сервере.

## Что теперь реализовано

На существующей закрытой странице предпубликационной проверки CMS появилась кнопка «Одобрить эту редакцию и запросить закрытую выгрузку». Она видна только администратору MoonShine, при включённых параметрах MUSEUM_ENABLE_APPROVAL_QUEUE=true и MUSEUM_USE_PUBLISH_QUEUE=true, постоянной database/redis-очереди и общем database/redis cache/lock, успешной проверке опубликованных материалов.

Запрос POST защищён аутентификацией и Laravel CSRF. Сервер повторно загружает сохранённую редакцию, формирует SHA-256 её полей, документов, медиа и связей и сравнивает с отпечатком из предпросмотра. Изменившаяся редакция вызывает HTTP 409. Черновики, публикации с будущей датой, просроченные материалы и критические ошибки блокируются HTTP 422.

Создаётся отдельная приватная запись museum_content_approvals с actor ID, ID материала, SHA-256 редакции, реальным временем UTC, статусом постановки в очередь и publication_run_id. Повторное нажатие не меняет первоначальный approved_at и не дублирует запуск. Запуск приватной выгрузки происходит после записи одобрения в базу. При ошибке очереди сам факт одобрения остаётся сохранённым, статус failed, ответ HTTP 503; повтор допускает восстановление.

Добавлен закрытый журнал /admin/museum-content/approval-journal, доступный только администратору. Он показывает последние 100 записей без текстов черновиков, имеет no-store, noindex и ограниченную CSP. Обычное редактирование, смена status=published и почасовой cron не создают события одобрения.

**Безопасное значение по умолчанию:** MUSEUM_ENABLE_APPROVAL_QUEUE=false. Новая миграция лишь создаёт таблицу и не включает фоновые задания на Mac mini или серверах музея.

## Блокеры полного исполнения TZ-110

1. Нынешний экспорт всё ещё считает status=published пригодным к выводу в публичный JSON: новый журнал пока не является обязательным approval gate для всех типов контента. Включать режим в эксплуатацию до решения этого вопроса нельзя.
2. Сохранённый материал может измениться после одобрения до исполнения worker. Требуется повторная проверка одобренного отпечатка при фактической сборке, привязка к неизменяемому snapshot и защита от гонок.
3. Утверждённая редакция ещё не проходит через подтверждённый выделенный межконтурный канал музея к публичной странице. Нет независимого подтверждения появления конкретной версии по HTTPS и доказательства задержки менее 60 минут.
4. С музеем надо согласовать роли утверждающих, повторное утверждение при правках, правило снятия с публикации и процессы вне рабочего времени.
