# Исправление доступа к xlrd после Homebrew Python upgrade

16 октября 2026. На Mac mini Homebrew `python3` обновился до **3.15.0**; глобальная среда не содержала `xlrd`, ранее доступный только системному `/usr/bin/python3` (3.9). Прежний вызов PHP-конвертера через простой `python3` приводил к отказу при загрузке XLS.

## Устранено на ArvectumSSD

- Создан локальный изолированный Python venv внутри репозитория **`.venv/`** и установлена фиксированная зависимость `xlrd==2.0.2`. `.venv/` не попадает в Git, релизный ZIP или публичный сайт.
- PHP `MuseumLegacySpreadsheetNormalizer` использует `config('museum.xls_python', 'python3')`, а на Mac mini в приватном `apps/cms/.env` задан `MUSEUM_XLS_PYTHON=/Volumes/ArvectumSSD/arvectum/repos/musbread/.venv/bin/python`. Изменять системный `python3`, устанавливать зависимости глобально и отключать PEP 668 больше не нужно. Параметр опционален, поэтому CI продолжает работать с собственным системным Python и установленным в workflow `xlrd==2.0.2`.
- Для восстановления среды при обновлении Homebrew Python: `bash scripts/setup_xls_python.sh`. Скрипт создаёт/обновляет venv и повторно устанавливает зависимости из `scripts/requirements-xls.txt`. Если Homebrew удалил старую версию Python, а venv перестал запускаться, достаточно пересоздать каталог `.venv` (только после явной проверки, что это локальный venv проекта) и снова выполнить скрипт; основной код/содержимое CMS не затрагиваются.
- Конвертер **в production по-прежнему запрещён**, пока заказчик не подтвердит антивирусную обработку XLS. Старые файлы сразу преобразуются в XLSX без исполнения формул/макросов; входной XLS не хранится. Проверены реальная конверсия синтетического `tests/fixtures/synthetic-legacy.xls` и `MuseumDocumentsTest` с обычным PATH Homebrew.
