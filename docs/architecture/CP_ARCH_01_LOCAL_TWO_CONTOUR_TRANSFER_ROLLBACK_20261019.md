## Что сделано на Mac mini без участия музея

Создан воспроизводимый [изолированный Docker-тест](../../scripts/verify_museum_two_contour_docker.py). Он запускает три одноразовых контейнера и две изолированные Docker-сети:

```text
    PRIVATE, --internal                      PUBLIC, host 127.0.0.1:18089 only
 ┌─────────────────────┐                  ┌──────────────────────────────────┐
 │ PHP 8.4 / private   │                  │ Nginx / public                   │
 │ export surrogate    │                  │ Only read-only static files     │
 │ NOT Laravel/MoonShine│                 │ Cannot see PHP/CMS private dir  │
 └──────────┬──────────┘                  └──────────────────┬───────────────┘
            │                                                │
            └──> COURIER (dual-net, trusted manifest) ───────┘
                  copies verified files into Docker volume RW
                                    public volume mounted read-only in Nginx
```

Оригинальный сайт музея / его серверы / DNS / Reg.ru / домен Арвектума **не затрагивались**. Контейнер CMS **не имеет опубликованного порта**, контейнер публичного Nginx **не состоит в private Docker-сети**, контейнер CMS **не состоит в public Docker-сети**. Единственный участник обеих — промежуточный контейнер. CMS → public и public → CMS **напрямую не маршрутизируются**. Доступ к тестовому публичному HTTP только `127.0.0.1:18089` Mac mini. Исходные материалы и файлы состояния остаются на ArvectumSSD; все временные сети, контейнеры, volume и файлы теста после проверки удаляются.

**Важно о масштабе:** внутри приватного контейнера используется **PHP 8.4 surrogate для передачи контрольного архива**, а не запущенный Laravel/MoonShine. В пакет входят **пять настоящих файлов из уже собранного `apps/web/out`**: `index.html`, `robots.txt`, `sitemap.xml`, `novosty/index.html`, одно WebP из музейного корпуса. Это реальный тест Docker-сетей и доставки, а **не интеграция всех 101 PDF, 303 WebP и 467 HTML** или интеграция с сетью музея. Последние отдельно проверялись настоящим HTTP на локальном Nginx в [CP-SEO-06](../seo/CP_SEO_06_REAL_NGINX_LOOPBACK_20261019.md). Редактирование и контроль экспорта настоящей CMS проверялись отдельно в PHP feature-тестах.

**Обнаруженный инженерный нюанс:** атомарная замена symlink на **Mac host bind mount** не сразу становилась видимой в Linux Docker VM. При реальном HTTP-тесте это выявило задержку старого контента. После переноса публичного каталога релизов во **внутренний Docker named volume**, который монтируется Nginx только для чтения, а courier — на запись, переключение и откат корректно отрабатывают по HTTP. Не использовать macOS bind-mounted symlink в качестве доказательства атомарного Linux-деплоя музея.

## Что нельзя заявлять завершённым

- **Нет** работающего защищённого внутреннего канала музея, доверенных IP и отдельного реального серверного сегмента заказчика.
- В частном Docker-сценарии для наглядности используется **изолированный HTTP между контейнерами**, а не согласованная с ИБ музея криптографически аутентифицированная транспортная подпись. SHA-256 без защиты sidecar **не удостоверяет происхождение** — в промышленном канале нужны аутентификация отправителя, защита от replay и доверенное соединение.
- Нет подключённого industrial автоматического `Laravel queue -> Next build -> protected transfer -> Nginx activation` с настоящим одобрением редактора, а значит соблюдение 60-минутного SLA **не подтверждено на рабочих серверах**.
- Не выполнялись публичное HTTPS/TLS 1.2+, пентест, настоящие интеграции с билетами/почтой/аналитикой, нагрузка на сервер музея и приёмка.

**Светофор требований ТЗ не повышаем искусственно:** TZ-104–107 и гарантийно-инфраструктурные пункты остаются частичными до настоящей интеграции и передачи заказчику. Контроль всей матрицы — **325: 🟢84 / 🟡102 / 🔴139**. Для окончания доконтрактной стадии не требуется отдельный Reg.ru и не нужен доступ на сервер музея.
