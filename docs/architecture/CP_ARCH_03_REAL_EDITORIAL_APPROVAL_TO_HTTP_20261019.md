# CP-ARCH-03 · настоящее редакционное одобрение → публичный HTTP · 19.10.2026

**Итог: PASS на изолированном Mac mini; соответствие 60-минутному SLA на инфраструктуре музея ещё НЕ доказано.** Основание: пп. 2.2.3.4–2.2.3.5 оригинального ТЗ № 0372200172326000015. Это продолжение CP-ARCH-01/02, а не новые требования о `www`, Яндекс Вебмастере или хостинге на Reg.ru.

## Что теперь проверено полностью, а не по отдельности

1. В тестовом процессе Laravel создаётся совершенно **отдельная in-memory SQLite**, а две реальные CMS-сущности — QA-новость и QA-событие — публикуются только в этой тестовой базе. Третий материал оставлен **неодобренным черновиком**.
2. Тест входит в реальный Laravel HTTP-маршрут `museum.entries.approve-and-queue` и соответствующий маршрут события как **MoonShine-администратор**, передавая настоящие SHA-256 редакций. Контроллер, а не ручное редактирование таблицы, фиксирует `approved_at` и запись автора решения. Проверяются **2 одобрения и ровно 1 объединённая очередь**.
3. Вызывается реальный `queue:work` (соединение `database`, очередь `museum-publish`, `--once`). Обработчик проверяет строгий preflight, подписи утверждённых редакций и формирует JSON с SHA-256-манифестом в отдельном приватном staging. Проверяются статус `succeeded`, одна попытка, пустые `jobs` и `failed_jobs`, отсутствие черновика.
4. Фиксируется **подлинный UTC `approved_at` контроллера**. Отдельно измеряется время до окончания экспорта, затем Next.js собирает новый сайт из этого JSON. Временно исключён только postbuild скрипт миграции старых адресов, не относящийся к QA-материалам. Исходные 555 путей музея и рабочая CMS-БД не затронуты.
5. Полученная QA-страница вместе с пятью статическими файлами передаётся по внутренней Docker-сети единственным промежуточным контейнером; проверяются SHA-256, неизменность пакета, изоляция CMS и публичного Nginx, read-only web volume. **Реальный Nginx по HTTP возвращает точные байты статьи, на которую было нажато «Одобрить».** Повреждение пакета отклоняется, переключение тестовой версии и откат восстанавливают прежнюю страницу.
6. После измерения все тестовые файлы, контейнеры, сети и тома удаляются. Действующий сайт музея, домен, поисковый индекс, продакшн-БД и хостинг Arvectum не изменялись.

## Оставшиеся блокеры — только в пределах ТЗ

- Сценарий выполняет настоящие контроллер и queue-worker **на Mac mini**, но приватный Docker endpoint продолжает имитировать **транспортный** сервис, а не готовую защищённую сеть Laravel на сервере музея. Сервер и доверенные IP предоставит заказчик после договора.
- В реальной инфраструктуре потребуются защищённый авторизованный канал, разнесённые веб- и CMS-сервера, проверенная периодическая/событийная доставка, мониторинг повторных заданий и соблюдения SLA при отказах, внешний TLS/пентест по ТЗ. SHA-256 файла без аутентификации отправителя **не является подписью источника**.
- Прямое CMS → публичный Nginx соединение недоступно в QA; материал доставляется через отдельный courier, как предусмотрено моделью. Закрытые QA-редакции не допускаются к публичному релизу музея.
- Уже существующие PHP-тесты проверяют изменения материалов после одобрения, устаревшие SHA-256, повторные запросы и запрет неавторизованного согласования; данный этап добавил **измеренный локальный сквозной сценарий**.
