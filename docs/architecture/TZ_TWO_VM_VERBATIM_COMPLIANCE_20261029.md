## Принятое техническое толкование

**ВМ2:** только Nginx и статика; единственный маршрут HTTPS POST /v1/requests передаёт данные по закрытой сети через mTLS на отдельную службу ВМ1, не открывая CMS или БД. Nginx должен не сохранять даже временные файлы POST (max 8 KiB, body buffer 16 KiB, request/response buffering off, access_log off), не добавлять API в публичную Next.js-сборку.

**ВМ1:** защищённые Laravel/MoonShine/БД и Next.js build; отдельно изолированный PHP-FPM приёмщик с публичным ключом и зашифрованной очередью. CMS самостоятельно забирает заявки, сотрудники проводят модерацию и контроль через защищённую административную панель с доступом только с доверенных IP. На служебный 9443 допускается только mTLS с приватного IP ВМ2, отсутствуют любые маршруты CMS.

## Обязательные стоп-гейты

1. На предоставленных ВМ подтвердить разделение служебного канала приёма и доступа к CMS, соответствие формулировке об обработке данных исключительно из бэкенда. В случае невозможности — изменить реализацию, не просить смягчить ТЗ.
2. Отрицательные сетевые тесты: с публичной ВМ нет доступа к CMS, СУБД, SSH, внутренним pull/ack и административным портам; с внешнего интернета нет доступа к закрытой ВМ.
3. Реальная проверка отсутствия ПДн на диске ВМ2, включая сбои, большие POST, логи и файловый кэш Nginx.
4. Утверждённые оператор ПДн, согласие, срок хранения/удаления, регламент ответа, реальные роли редакторов и UAT.
5. Серверные нагрузочные испытания, пен-тест, TLS, отказоустойчивость, копирование/восстановление и SLA.

**Заключение:** Nginx reverse proxy сам по себе не отступление от ТЗ, но целевая архитектура ещё не доказала полное соответствие на реальных ВМ. Серверный приём заявок остаётся выключенным, mailto — временное решение. Открытые TZ-080/081/085/091/203/204 не закрыты.
