# Архитектура MusBread (предконтрактная)
> **Обновление 29.10.2026:** интерактивные функции и границы доверия описаны в [ADR](decisions/ADR_20261029_PUBLIC_INTERACTIONS_WITH_STATIC_EXPORT.md). Поиск и официальные ссылки уже реализованы, а отдельный шлюз приёма реальных обращений пока **не развёрнут**. Публичный сайт остаётся статическим; правовая модель и сеть должны быть согласованы с музеем.

Основание — пп. 2.2.3.2–2.2.3.7 технического задания. Все предположения уточняются по итогам обследования сети музея.

## Контур управления (закрытый)
Laravel PHP 8.4+; MoonShine для ролей/контента; SQL database; очереди и scheduler; audit; медиатека; запланированная публикация; API экспорта **только внутри закрытого контура**.
В реальной инфраструктуре — сервер в защищённом сегменте музея с доступом по доверенным IP.

## Publisher (граница доверия)
1. Редактор утверждает контент.
2. Внутри закрытого контура генерируется детерминированный snapshot: version, timestamp, schema_version, items, hashes.
3. SHA-256 и проверка schema перед выпуском.
4. Только разрешённые опубликованные записи попадают в экспорт (без draft, персональных данных и секретов).
5. По выделенному закрытому каналу обновление передаётся в public release staging. Проверка checksum, атомарная смена текущей версии, журнал и rollback.
6. Публикация каждый час или по команде. Разрешения сети и канал — после обследования.

## Публичный контур
Next.js в режиме статического экспорта; Nginx отдаёт HTML/CSS/JS/media и кэш. Публичная выдача не делает запросов к Laravel, не хранит CMS/DB и не требует backend для чтения материалов.
Поиск — предрассчитанный статический индекс. SEO: sitemap, robots, alt, метаданные и JSON-LD.
Билетная система/формы ПДн пока реализуются адаптерами, а не фиктивными платежами; архитектура согласуется с музеем.

## Разработка vs промышленный запуск
В dev оба компонента могут запускаться на Mac mini/Docker. Это **не доказывает** защищённой физической сегментации: production deployment и pentest требуют инфраструктуры музея.

## ADR
1. GitHub = source of truth, GitVerse = mirror; GitHub Actions secret для GitVerse.
2. Public repo — никаких реальных доступов, ПДн, неопубликованных материалов клиента.
3. Ветка main должна проходить CI.
4. Промежуточные результаты нельзя обозначать как принятую заказчиком работу.

## Queue/worker recovery (pre-award)

Queue используется только при MUSEUM_USE_PUBLISH_QUEUE=true и постоянно работающем worker. По умолчанию прямой почасовой экспорт оставлен для простого dev. При включении queue безопасное восстановление запускается каждые 10 минут: запросы queued старше 120 минут и running старше 45 минут переводятся в terminal abandoned **только при свободной блокировке экспортёра**. Отложенные задачи abandoned не выполняются. Для заказчика нужно настроить worker не дольше 600 сек, retry_after >=900 сек, мониторинг остановок, реальное ограничение retries и настроенную БД. Параметры после обследования. Промышленный транспорт в защищённый контур пока отсутствует.
