# MusBread — интеграции, границы и открытые вопросы

Источник требований: docs/REQUIREMENTS.md, п. 2.2.3.6.4. Для билетов **сохранён существующий официальный переход музея на ВМузей**, без собственного приёма оплаты и без API. Остальные сервисы и боевые настройки потребуют подтверждения заказчика. Разработка дизайна временно на паузе по решению исполнителя.

| Сервис | Контур | Какие данные потребуются | До интервью |
|---|---|---|---|
| Билеты | **Прямая HTTPS-ссылка ВМузей из действующего сайта** | Существующий официальный URL, не API | **Уже подключена** в шапке, мобильном меню и разделе «Билеты и льготы»; покупка на стороне ВМузей |
| Запись на экскурсию | Закрытый backend либо согласованная сторонняя форма | Расписание, лимиты мест, разрешения на ПДн | Отключено, никаких броней |
| Карты | Только утверждённая ссылка/плеер на публичной статике | Точный адрес/координаты, API/лицензия | Без внешнего SDK |
| Аналитика | Публичная статика только после согласования | ID счётчика, consent, условия ПДн | Не подключена |
| Соцсети | Ссылки на публичной статике | Официальные URL и права на логотипы | Пустой список |
| Видео | Публичная статика, доступная текстовая альтернатива | URL, права, субтитры и транскрипты | Плеер отключён |
| Обратная связь | Только закрытый backend / утверждённый сервис | Получатель, хранение, согласие, антиспам | Отключено, ПДн не передаются |

Существующая кнопка **ВМузей — обычная публичная HTTPS-ссылка Next.js**, она не вызывает backend и не требует секретов, webhooks или хранения ПДн. В Laravel apps/cms/app/Integrations созданы семь видов интеграций, интерфейс IntegrationPort и координатор MuseumIntegrationHub. По умолчанию используется DisabledIntegrationPort: без сети, платежей, секретов и реальных заявок. DemoIntegrationPort тестирует статусы success/error/timeout, причём успех отмечен как MOCK; автоматический повтор тайм-аута не допускается. Разрешён только неидентифицирующий resource_slug.

В Next.js apps/web/src/integrations/public.ts содержатся типизированные публичные ссылки (билеты, карты, соцсети, видео). Официальная билетная ссылка доступна без отдельного API и без дополнительного editorial approval для самого факта перехода (как и на действующем сайте); остальные новые интеграции не появляются без разрешения и требуют HTTPS, не включают credentials или секреты в query. Analytics, feedback и booking выключены. Базовая статика не обращается к Laravel и не содержит API-ключей.

## Вопросы музею до реальной интеграции

1. Билеты: **новый API не запрашивать**. После договора только проверить, что в ВМузей всё ещё доступны необходимые позиции прейскуранта (посещение, экскурсии, мероприятия и прочие), и при необходимости уточнить это у музея. Автоматический HTTP 200 у ВМузей не доказывает прохождения покупки: сервис показывает антибот-проверку.
2. Экскурсии: схема расписания, доступные места, лимиты/отмены, чья система хранит сведения посетителей.
3. Карты: подтверждённые адреса и координаты, выбор провайдера, доступные входы для маломобильных посетителей, лицензии.
4. Аналитика: точные метрики и провайдер, cookie consent и тексты о ПДн, оператор и сроки хранения.
5. Видео и соцсети: список официальных адресов, разрешения на изображения, субтитры/транскрипты и настройки CSP.
6. Обратная связь: адрес получателя, антиспам, где хранить обращения, юридические основания и допустимые сроки.
7. Инфраструктура: сетевые границы, firewall, outbound allow-list закрытого сегмента, сертификаты, кто выдает секреты.

## После официального допуска

**Билеты:** никаких дополнительных адаптеров и API не планируем — пользователь сохраняет официальный переход на ВМузей. **Для иных сервисов**, если ТЗ требует серверный обмен, только после предоставления API и соответствующего согласования создавать адаптер конкретного поставщика. Протокол испытаний должен охватывать тестовые операции, 429/5xx, тайм-ауты, двойные отправки, неизвестный статус заказа, безопасность ПДн и отсутствие токенов в браузерной сборке. Реальные платежи и персональные данные не тестировать без разрешения.
