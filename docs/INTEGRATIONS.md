# MusBread — интеграции, границы и открытые вопросы

Источник требований: docs/REQUIREMENTS.md, п. 2.2.3.6.4. Поставщики билетной системы, карты, аналитики и записи музеем ещё не подтверждены. Нижеследующее — только контрактная подготовка, **не реальные подключения**.

| Сервис | Контур | Какие данные потребуются | До интервью |
|---|---|---|---|
| Билеты | Публичная HTTPS-кнопка + закрытый backend при необходимости | Платформа, события, тарифы, ссылка/API, webhook | Отключено, покупок нет |
| Запись на экскурсию | Закрытый backend либо согласованная сторонняя форма | Расписание, лимиты мест, разрешения на ПДн | Отключено, никаких броней |
| Карты | Только утверждённая ссылка/плеер на публичной статике | Точный адрес/координаты, API/лицензия | Без внешнего SDK |
| Аналитика | Публичная статика только после согласования | ID счётчика, consent, условия ПДн | Не подключена |
| Соцсети | Ссылки на публичной статике | Официальные URL и права на логотипы | Пустой список |
| Видео | Публичная статика, доступная текстовая альтернатива | URL, права, субтитры и транскрипты | Плеер отключён |
| Обратная связь | Только закрытый backend / утверждённый сервис | Получатель, хранение, согласие, антиспам | Отключено, ПДн не передаются |

В Laravel apps/cms/app/Integrations созданы семь видов интеграций, интерфейс IntegrationPort и координатор MuseumIntegrationHub. По умолчанию используется DisabledIntegrationPort: без сети, платежей, секретов и реальных заявок. DemoIntegrationPort тестирует статусы success/error/timeout, причём успех отмечен как MOCK; автоматический повтор тайм-аута не допускается. Разрешён только неидентифицирующий resource_slug.

В Next.js apps/web/src/integrations/public.ts содержатся типизированные публичные ссылки (билеты, карты, соцсети, видео). Они не появляются без явного editorial approval, требуют HTTPS, не включают credentials или характерные секреты в query. Analytics, feedback и booking выключены. Базовая статика не обращается к Laravel и не содержит API-ключей.

## Вопросы музею до реальной интеграции

1. Билеты: название и техконтакт платформы, актуальные API/deeplink/iframe, тестовая среда, webhooks, возвраты, комиссии и idempotency.
2. Экскурсии: схема расписания, доступные места, лимиты/отмены, чья система хранит сведения посетителей.
3. Карты: подтверждённые адреса и координаты, выбор провайдера, доступные входы для маломобильных посетителей, лицензии.
4. Аналитика: точные метрики и провайдер, cookie consent и тексты о ПДн, оператор и сроки хранения.
5. Видео и соцсети: список официальных адресов, разрешения на изображения, субтитры/транскрипты и настройки CSP.
6. Обратная связь: адрес получателя, антиспам, где хранить обращения, юридические основания и допустимые сроки.
7. Инфраструктура: сетевые границы, firewall, outbound allow-list закрытого сегмента, сертификаты, кто выдает секреты.

## После официального допуска

Только после предоставления API и письменного согласования создать адаптер конкретного поставщика. Протокол испытаний должен охватывать тестовые операции, 429/5xx, тайм-ауты, двойные отправки, неизвестный статус заказа, безопасность ПДн и отсутствие токенов в браузерной сборке. Реальные платежи и персональные данные не тестировать без разрешения.

## Воспроизведение

PHP: cd apps/cms && php artisan test --filter=MuseumIntegrationsTest.
TypeScript: cd apps/web && npm run test:integrations.
