## TZ-223 — безопасные публичный и приватный Nginx

До этого этапа существовали два template server-block: статический root на 127.0.0.1:18080 с CSP и закрытый CMS на 127.0.0.1:18082 с FastCGI к /run/php/php8.4-fpm.sock. HTTP smoke и nginx -t уже есть в Linux CI.

Точечная правка: публичный Nginx отклоняет не только /admin, /api, /storage, /vendor, но и /database, /bootstrap, /config и /private. Это защита от случайного копирования закрытых файлов в root публичного релиза, а не новая архитектура. В GitHub CI добавлены HTTP проверки попыток скачать подложенный файл из /database и получить приватные пути. Проверка конфигов настоящим Linux Nginx в **одноразовом Alpine-контейнере** на Mac mini: nginx -t проходит; /database/private.txt возвращает HTTP 404, хотя тестовый файл существует под public/current. Тест не открывает публичный порт Mac или сервер музея.

## TZ-224 — проверка именно FPM, не PHP CLI

Создана read-only проверка scripts/check_php_fpm.py:
- запускает *сам* php-fpm (-v/-tt), требует fpm-fcgi и версию >=8.4;
- проверяет единственный разрешённый listener/pool для этого шаблона;
- может сверить фактический listener с ожидаемым Unix socket и путём fastcgi_pass в Nginx;
- не запускает daemon, не показывает конфигурационные секреты при ошибке, не меняет файлы;
- отрицательные тесты: CLI вместо FPM, FPM 8.3, неверный socket, несколько pool listeners.

На Mac mini реально установлен и прошёл проверку **PHP-FPM 8.4.26**, pool слушает 127.0.0.1:9000. Это НЕ Unix-сокет будущего Linux, и такой запуск **не доказывает** готовность TZ-224 на сервере заказчика. Для целевого Linux после установки администраторами: python3 scripts/check_php_fpm.py --binary /usr/sbin/php-fpm8.4 --expected-listen /run/php/php8.4-fpm.sock --nginx-template infra/nginx/private-cms.conf.

## TZ-225 — запуск защищённого Laravel worker через systemd

Доработан существующий infra/systemd/musbread-publisher.service, не создавался второй worker:
- ExecStartPre выполняет штатный Laravel cache/queue-check перед началом очереди; отказывает при выключенной очереди, неправильном queue driver, retry_after <900 или неработающем общем кешировании/эксклюзивных блокировках.
- Рабочий таймаут 540 секунд (per-job hard timeout; failOnTimeout=true) при retry_after >=900. Исправлена старая ошибочная инструкция timeout=900, которая могла вести к повторной выдаче ещё выполняющейся задачи.
- Restart=always заменяет on-failure, чтобы worker поднимался после нормального выхода; RestartSec=15 и StartLimitBurst=5/300 секунд предотвращают бесконечные частые рестарты.
- Добавлен UMask=0027 для worker и scheduler. Уже действующий systemd timer запускает только один oneshot scheduler, не требуется второй cron.
- Ошибки конфигурации не означают разрешение открыть прямую запись в публичный webroot.

**Найденный блокер:** штатный Laravel export до согласования продакшн-каталога пишет в соседний ../web. Но существующий systemd ProtectSystem=strict разрешает запись только в storage и bootstrap/cache. Нельзя автоматически запускать worker, пока не согласован **приватный staging-каталог**, права записи и транспорт доставки в публичный контур; простое снятие защиты с systemd ради запуска запрещено. Документ infra/README.md и инструкция очереди требуют решить именно это после предоставления архитектуры музея.

## Регрессии и ограничения

- Python-тесты infra/systemd и проверки FPM + Laravel feature проверки cache/queue fail closed.
- Linux Nginx smoke выполняется в Docker-контейнере на Mac mini, GitHub CI повторит через nginx -t + curl.
- Состояние служб на реальном Linux (systemctl), реальный локальный FPM socket, TLS, доверенные IP, закрытый канал, хранение данных и SLA **не проверялись**.
- Никаких production-запусков, переноса контента музея или реального деплоя нет.

**Светофор:** TZ-223, TZ-224, TZ-225 остаются 🟡 «Частично», внешние блокеры: доступ к изолированным Linux-серверам, реальный PHP-FPM pool, согласование TLS/доменов/staging/публикационного канала, проверка systemd на целевых хостах и музейный UAT.
