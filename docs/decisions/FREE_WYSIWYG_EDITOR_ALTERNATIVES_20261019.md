# Замена TinyMCE: свободный визуальный редактор для Музея хлеба

**Дата проверки:** 19.10.2026 · **закупка:** 0372200172326000015 · **статус:** проверен автономный кандидат, замена в CMS **НЕ производилась**. Дизайн остаётся на паузе.

## 1. Точный объём ТЗ, без новых работ

По первичному реестру `docs/tz-audit/requirements.psv`:

- TZ-232, п. 2.2.3.7.2: **WYSIWYG с ограниченными операциями и безопасным медиа**;
- TZ-180–190, п. 2.2.3.6.3: текст, ссылки, изображения, видео, корректная HTML-разметка и SEO;
- TZ-308, раздел 4: **редактор должен управлять содержимым без навыков программирования**;
- TZ-309, раздел 4: редактирование страницы как **HTML-гипертекста**;
- TZ-313, раздел 4: **не нарушать права третьих лиц**.

ТЗ **не содержит требования применить TinyMCE, Jodit или включённый в реестр РФ редактор**. Российский реестр — предпочтение участника, но **не причина платить за редактор, добавлять проприетарные SDK или перестраивать CMS**. В ТЗ сохраняется требуемый Laravel/MoonShine, структура и права редактирования.

## 5. Условия безопасной замены TinyMCE без расширения ТЗ

1. Зафиксировать конкретную npm-версию **Jodit Community 4.18.4**, lock и `LICENSE.txt`; загружать JS/CSS только с нашего сервера, без CDNs, облаков и PRO-плагинов.
2. Интегрировать визуальное поле `body` в MoonShine через контролируемое поле с **точно тем же HTML-контрактом** (`body`, черновики, preview, роли, `MuseumHtmlSanitizer`, экспорт в Next). Никакого второго движка или базы.
3. Проверить реальные статьи: русский HTML, заголовки, списки, внутренние ссылки, изображения из нашего контролируемого медиахранилища, alt/caption, inline-маркеры видео. Удалить возможность произвольной загрузки непроверенных файлов, внешних ссылок/URL и base64.
4. Сохранить визуальное редактирование и **исходный HTML** для сотрудников, не требуя навыков разработчика. Проверить открытие/сохранение/повторное редактирование уже существующего текста, права редактора, XSS/CSRF и доступность клавиатурой.
5. Полная изолированная CMS HTTP/E2E, `Laravel → snapshot JSON → статический Next.js`, неизменность старого HTML и блокировка неутверждённых публикаций. Не переключать default до прохождения.
6. **Только затем** удалить `moonshine/tinymce`, исходные `.js`, устаревшие файлы vendor и GPL notice именно TinyMCE; пересобрать lock/Composer, CMS assets, SBOM/NOTICES, сравнить архив и откат.

**Решение исследования:** первоочередной кандидат **Jodit CE MIT**. Второй резерв — **Quill BSD-3-Clause**. Не менять текущую рабочую CMS автоматически на основании одного smoke-теста. Никаких новых задач сверх исходного функционала ТЗ и никаких оплат/учётных записей для внедрения Jodit не требуется.
