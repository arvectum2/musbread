# ADR-20261029 — Интерактивные функции при статическом публичном сайте

**Статус:** архитектурное решение Исполнителя для реализации; не равнозначно промышленной готовности или отдельному согласованию с Заказчиком.

**Основание:** договор № 03722001723260000150001, письмо № 20261027-3, ответ музея № 355 от 29.10.2026, п. 2, матрица `docs/tz-audit/requirements.psv`. ТЗ требует: CMS/СУБД в изолированном сегменте (TZ-099), публичный сервер **только со статикой и кэшем** (TZ-101), отсутствие доступа к CMS (TZ-102), выделенный внутренний канал (TZ-103).

**Техническое обновление 29.10.2026:** изолированный PHP sodium/SQLite приёмщик, закрытая Laravel-команда, read-only MoonShine-раздел, опциональная статическая форма и Nginx mTLS-шаблон реализованы в исходниках; описание эксплуатации находится в services/request-ingress/README.md. **Это не боевой deployment:** отсутствуют согласованные сегменты, сертификаты, правовой регламент, реальная приёмка заказчиком. Режим выключен по умолчанию.

## Проверенные реализации

| Функция | Решение | Что остаётся |
|---|---|---|
| TZ-120/177 поиск и автодополнение | Индекс из опубликованного CMS snapshot → Next.js Static Export → поиск в браузере без CMS API | Утверждённые материалы и UAT |
| TZ-198/205 билеты | Официальный HTTPS-переход во «ВМузей» без оплаты на нашем сайте | Проверка маршрута и ассортимента |
| TZ-199 карта | Официальная карта Яндекса с загрузкой по клику | Подтверждение адреса, политики и приёмка |
| TZ-201/202 соцсети и видео | Официальные VK/MAX ссылки; VK-видео по клику | Контент, права и UAT |
| TZ-080/081/203/204 заявки | `mailto:`-черновики посетителя + демонстрационная закрытая модель MuseumRequest | **Нет серверного приёма, регистрации реальных ПДн и подтверждения записи** |
| TZ-200 аналитика | Выключена | Счётчик, политика, согласие, проверка |

Реализация фронтенд-компонента `MuseumVisitorInquiryForm` не гарантирует отправку: пользователь сам отправляет письмо из своего почтового клиента. В `output:"export"` Next.js нет серверных POST/Server Actions; ради формы нельзя переносить Next.js runtime на публичный сервер.

## Целевая архитектура реальных обращений

Сохраняем **два согласованных контура сайта**. Если необходима полноценная HTTP-отправка формы, размещаем **отдельный минимальный шлюз приёма** в изолированной DMZ/сегменте, НЕ на публичном статическом сервере и НЕ в закрытой CMS. Шлюз не получает адреса/учётные данные CMS/СУБД и не может устанавливать к ним соединения.

```text
Браузер → GET → [публичный Nginx: статические HTML/CSS/JS]
        → HTTPS POST /v1/requests → [отдельный ingress]
                                      → валидация, антиспам, rate limit
                                      → зашифрованная durable очередь
 [закрытый Laravel / MoonShine] → mTLS pull по частному каналу → ingress
                     ↓
       проверка + идемпотентный импорт в закрытую БД
       журнал / статусы / назначение редактору / уведомления
```

Связь с ingress инициируется **только из защищённого сегмента** по выделенному частному маршруту, не через интернет (TZ-103). Ingress хранит зашифрованные пакеты без ключа расшифровки; секреты расшифровки и персональные данные — только в закрытом сегменте. Публичный статический веб-сервер не принимает POST, не хранит заявления, cookies/токены и не обращается к CMS.

Контракт `docs/architecture/visitor-interactions.v1.json`: только `feedback` и `excursion`; имя до 100 символов; текст до 1200; дата ISO и группа 1–100 — только для экскурсии; вложений, платежей и автоматического бронирования нет. До включения обязательны утверждённое уведомление/согласие по ПДн, правила хранения, адресаты и регламент заказчика. Максимальный размер тела — 8 КБ; антиспам, предел частоты, валидация полей и origin. Ответ **202** только после надёжной записи в очередь, означает «получено на обработку», **не бронь**. Worker выполняет import-once с дедупликацией и ack только после долговременного сохранения; повтор отправки не создаёт повторное обращение. При сбое — 503 без ложного «успешно».

Служба ingress потребует инфраструктуры, правил межсетевого экрана, сертификатов и регламента поддержки. Её физическое размещение, модель ответственности и стоимость согласуются с музеем: наличие архитектурного решения **не означает**, что дополнительная инфраструктура предоставлена или оплачена.

## Сторонние сервисы

- **Поиск:** только опубликованные материалы и статический индекс. Черновики и ПДн исключены. Приёмка релевантности — на реальном корпусе.
- **Билеты:** внешний переход, без платежного API и хранения карт.
- **Карты/видео:** по нажатию и с точным CSP allowlist; соцсети — обычные ссылки без активного трекинга.
- **Аналитика:** отключена до выбора заказчиком сервиса, согласования политики и управления согласием. Никаких скриптов третьих лиц до согласия; отказ/отзыв согласия блокирует дальнейший сбор.

## Границы завершения и приёмки

**Архитектурное решение определено:** компоненты, контракты, потоки и зоны доверия. **Реальная функция заявок остаётся незавершённой**, пока не реализованы шлюз и poller, не утверждены ПДн и не выполнен E2E на инфраструктуре заказчика. Нельзя объявлять TZ-080/081/203/204 зелёными на основании этого ADR.

Необходимые условия: (1) официальный регламент и поля музея; (2) правовая модель ПДн и сроки хранения; (3) выделенный сегмент/частный канал, mTLS и шифрование; (4) синтетические тесты 202/422/429/503, повторной доставки, XSS, отказов, логов без ПДн; (5) негативные сетевые тесты недоступности CMS извне; (6) UAT сотрудников музея; (7) независимые замеры 99% доступности, ≤60 минут публикации и ≤3 секунд загрузки на боевом стенде. Это **гейты**, а не уже пройденные испытания.

**Без изменений:** текущие статические формы `mailto:`, prod/DNS/сервера заказчика, CMS-БД и реальные персональные данные. Проект шлюза выключен до положительной приёмки.
