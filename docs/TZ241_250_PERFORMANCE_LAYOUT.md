## TZ-241 — лабораторные измерения

Создан воспроизводимый локальный скрипт `apps/web/scripts/qa-performance.mjs`: четырём публичным страницам на статическом сервере на Mac mini придаются 4× замедление CPU и сеть 150 ms RTT, 1,6 Mbps, в Chrome headless на 390px. Каждая из страниц измеряется с тремя новыми холодными браузерными контекстами. Записываются loadEventEnd, DOMContentLoaded, FCP, LCP, объём ресурсов и 75-й перцентиль, без внешних сервисов. Все частные отчёты сохраняются в закрытый SSD `.local_archive/system-disk-20261016/tz241-local-benchmark.json`; он не включён в Git.

| Тестовая страница | p75 `load` (мс) | p75 LCP (мс) |
|---|---:|---:|
| `/` | 3007 | 920 |
| `/news/` | 2958 | 900 |
| `/guide/museum/` | 3000 | 904 |
| `/search/` | 2957 | 900 |

**Вывод:** p75 LCP в локальной лаборатории ниже 1 с, но `load` главной страницы вышел за 3000 мс на 7 мс, остальные показатели близки к пределу. **Это НЕ подтверждение исполнения строгого ТЗ о «большинстве устройств».** Нужен замер в реальных браузерах и устройствах посетителей при целевых сетях, сервере и утверждённых фотографиях/шрифтах, включая WebPageTest/Lighthouse/field data; тогда оптимизировать найденные узкие места. Скрипт не назначает зелёный статус. Нет оснований подменять LCP метрикой полного load или наоборот.

Запуск на SSD после `npm run build`:

```bash
cd /Volumes/ArvectumSSD/arvectum/repos/musbread/apps/web
node scripts/qa-performance.mjs /Volumes/ArvectumSSD/arvectum/repos/musbread/.local_archive/system-disk-20261016/tz241-local-benchmark.json
```

## TZ-250 — ширина экрана

Ранее уже существовал CSS-контракт `@media(min-width:1001px){.hero,.section,.closing-banner{max-width:none;width:90%}}`, который перекрывает старое ограничение `max-width:1440px`. Поэтому CSS заново не переписывался. Добавлен регрессионный Playwright `apps/web/e2e/tz250-layout.spec.ts`: главная, новости, раздел каталога; ширины 1100, 1440, 1920, 2560, 3840 CSS px — **15 комбинаций**, у каждой внешний контейнер основного контента не менее 80% ширины viewport и нет горизонтальной прокрутки. Внутренние текстовые колонки ограничены по длине строк ради читаемости. Проверки прошли.

**Остаётся:** верификация на реальных мониторах, в утверждённом дизайне с реальным содержимым, проверка критериев читаемости пользователями музея. Нет оснований считать 15 точек достаточными для всех платформ. Статус **Частично**, внешний UAT блокер.

## 19.10.2026 — CP-TZ241-03, реальный локальный Nginx с gzip

[Протокол замеров](performance/CP_TZ241_03_PREFETCH_AND_NGINX_BENCHMARK_20261019.md). После прекращения фоновой Next.js prefetch-нагрузки 15 browser E2E PASS. Реальный localhost Nginx в лаборатории Chrome при CPU×4, 1,6 Мбит/с и 150 мс RTT показал 1,421 / 1,809 / 1,511 / 1,419 с p75 полного load для главной, новостей, музея и поиска. В Python-режиме без gzip эти же p75 составляют 4,000 / 8,841 / 4,675 / 3,906 с. Это измерение другого HTTP-пути, а не доказательство ускорения исключительно от отключения prefetch. Из-за отсутствия окончательной инфраструктуры и полевой проверки **TZ-241 остаётся частично выполненным**.
