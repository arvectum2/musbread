# TZ-136 / TZ-147 / TZ-242 — обложки событий из утверждённой медиатеки

**17 октября 2026 · MusBread · предконтрактный прототип · Mac mini / ArvectumSSD**

## Исходные требования и официальные материалы

Проверены строки атомарного ТЗ: TZ-136 (п. 2.2.3.6.1, строка 189: медиа); TZ-147 (там же, строки 199–200: все события в карточках/баннерах); TZ-242 (п. 2.2.3.8.1, строка 285: лёгкий лаконичный дизайн без тяжёлых баннеров/скриптов и анимаций).

До реализации существовали: медиатека с защищённой загрузкой PNG/JPG/WebP/GIF/SVG с перекодированием/очисткой в WebP, обязательным alt, подписью, длинным описанием и правами редакторов; прямые фото только в опубликованных CMS-материалах; события афиши уже в карточках с декоративной графикой, но без назначаемой фотографии.

Прямым запросом с Mac mini проверены https://muzei-xleb.ru/novosty (200, 24 тега img, 17 непустых alt), https://muzei-xleb.ru/vistavky/tekushchie-vystavki (200, 9 изображений, все с непустыми alt), https://www.spbmuseum.ru/ (200, музейные анонсы). На актуальном сайте Музея хлеба 17.10.2026 уже есть фотографии выставок и новостей — **не создавать/подменять их нейросетью** и не копировать на публичный прототип без подтверждения музеем прав и актуальности конкретного события. Отсутствие разрешённых изображений не является причиной выпускать фальшивую музейную афишу.

## Реализовано

**MoonShine:** в прежней форме события добавлен необязательный список «Обложка» из существующих изображений *публикуемых* материалов. Не создан второй загрузчик и хранилище для афиши. БД содержит необязательный cover_media_id с внешним ключом на museum_media и ON DELETE SET NULL. Сохранение требует, чтобы изображение принадлежало опубликованному действующему материалу **того же редакторского раздела**, и не допускает чужой раздел/снятый с публикации/черновик. Ресурс события сохраняет прежние права редактора.

**Статический экспорт:** событие получает cover_image только если источник существует в *той же утверждённой публичной выгрузке*. Проверяется целостность sha256 и действительный безопасный WebP стандартным экспортом медиатеки; поля alt/caption/long_description берутся из одного одобренного авторского файла. Если материал снят с публикации, перепубликация не происходит и обложка исчезает. Если изображение удалено, внешний ключ сбрасывается автоматически. Нет прав на изображение → редактор не выбирает и не публикует его.

**Next.js:** вместо декоративного символа EventCard на главной, в календаре/архиве и афише выводит выбранное событием изображение с исходным alt и loading=lazy; при его отсутствии остаётся прежний нейтральный placeholder. В полной странице события изображение, подпись и длинное описание отображаются как доступные текстовые элементы. Никаких autoplay, фоновых видео, новых скриптов сторонних галерей, повторных загрузок или глобальной предварительной загрузки тяжёлых баннеров.

## Подтверждение и негативные проверки

Новые PHP feature-тесты: валидный WebP с digest в выгрузке, перенесённый alt/подпись/длинный текст, немедленное исчезновение из выгрузки при переводе владельца в черновик, восстановление после публикации, null FK и отсутствие обложки при удалении, отказ при межраздельном или неопубликованном источнике, запрет гостевого изменения, отсутствие черновиков в списке вариантов MoonShine.

Изолированный тест **реальной** MoonShine: создание события → публикация новости → безопасная загрузка WebP к новости → изменение alt/подписи → выбор её же фотографии в редакторе события → статическая выгрузка → HTML карточки события в афише и полной страницы с точным alt, подписью и длинным описанием. Одно фото/один SHA-256 файл. Другое событие не получает содержимое изображения. Реальная тестовая SQLite, учётная запись, сервер создаются в одноразовом каталоге и удаляются.

Локальный sqlite `apps/cms/database/database.sqlite` перед миграцией скопирован только на ArvectumSSD (`.local_archive/db-backups/musbread-before-tz147-20261017.sqlite`); после `php artisan migrate --force` `PRAGMA integrity_check = ok`.
