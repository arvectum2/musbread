## Архитектура по ТЗ, без ненужного усложнения

В проекте уже есть MoonShine, записи MuseumEntry, документы MuseumDocument, навигация MuseumSection и статический экспорт. Не создавали новых таблиц, CMS, хранилищ или сервиса синхронизации.

Добавлена одна явная команда: php artisan museum:import-official-pages. По умолчанию **только план** без сетевых запросов и изменения БД. С флагом --apply создаёт только отсутствующие записи типа page в статусе draft, привязывает к готовой музейной структуре, сохраняет дату/URL официального источника в excerpt. Уже существующие материалы, редакторские правки, статусы и вложения не изменяет. На production массовый --apply запрещён, работать можно через обычные действия редактора. Для таблиц официальных цен стандартный HTMLPurifier разрешает только безопасную таблицу, без JS и атрибутов событий.

С --apply --documents валидные локальные оригиналы привязываются в приватном Laravel storage. Проверяется URL и наличие ссылки непосредственно в HTML первоисточника, точные длина и SHA256, штатный MuseumDocumentInspector, формат и лимит 15 МиБ. Непрошедшие проверку файлы остаются только официальными ссылками из исходного HTML; лимит не обходится. Проверка доступности файлов не помечается выполненной.

Подтверждение работоспособности экспорта не равнозначно публичному размещению на музее.

## Следующая техническая проверка: CMS → публичная страница /guide

Устранён практический пробел: на /guide/slug/ только **уже опубликованная** CMS-страница теперь является источником не только основного текста, но и H1, SEO-описания, SEO-заголовка и прикреплённых MuseumDocument. PDF/DOCX отображаются как проверенные при экспорте локальные /documents/sha256.ext с форматом и размером. Для файлов с accessibility_reviewed=false прямо показано, что доступность ещё не подтверждена. Когда запись ещё draft — текущая официальная справочная версия сохраняется, без показа закрытых вложений. При переходе к редактируемой публикации старый фиксированный каталог ссылок не дублируется, иначе редактор не мог бы убрать устаревший документ. Текущая страница не появляется собственной ссылкой в блоке «Материалы раздела».

Это **не новая CMS, новый бэкенд или отдельный контентный сервис**: доработан уже существовавший шаблон и проверен уже работающий штатный JSON-экспорт. Реальные черновики не публиковались. В scripts/qa_official_cms_guide.py создан воспроизводимый проверочный скрипт, который берёт **консистентную копию** SQLite с Mac mini в одноразовом каталоге на ArvectumSSD, меняет статусы и тестовые заголовки **только в копии**, экспортирует два CMS-материала и один PDF с SHA-256, собирает новый статический Next.js из копии исходников, проверяет H1/title/description, оригинальную таблицу цен, публикацию PDF, ссылку на документ и доступность, сохранность fallback для третьего неопубликованного материала и запрет индексации (noindex). После проверки одноразовая БД/сборка/файлы удаляются, 8 рабочих черновиков и публичный published.json не меняются. Это локальное QA, не публичный релиз заказчика.
