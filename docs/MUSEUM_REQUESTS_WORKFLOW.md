# CP-25D — внутренние обращения и заявки на экскурсии

Основание: ТЗ №0372200172326000015, п. 2.2.3.2 (TZ-080/081/085/091), 2.2.3.6.4 (TZ-203/204); правовые требования 152-ФЗ (TZ-282) и 59-ФЗ (TZ-283).

Статус: **только рабочий предконтрактный демонстрационный реестр**. Нет публичной формы и сбора реальных персональных данных. Демо-обработка не означает юридически завершённого обращения.

## Реализовано

- [x] Отдельные таблицы museum_requests и museum_request_transitions. Нет имени, телефона, почты, IP, сообщения, вложений заявителей в таблице.
- [x] Два типа: обратная связь и запись на экскурсию; справочные темы строго из списка. Для экскурсии предусмотрены дата и группа от 1 до 100 человек.
- [x] Закрытый ресурс «Обращения (демо)» в MoonShine: автоматически созданный номер DEMO-ULID, тип/тема, статус, раздел сайта, назначенный сотрудник, дата создания.
- [x] Гранулярные права: администратор может создать тестовую карточку и назначить ответственного с правом на нужный раздел. Редактор видит только назначенные ему обращения в разделах с разрешением, меняет только статус. Попытки чужого POST/PATCH запрещены.
- [x] Статусы: new → triaged → in_progress → resolved, а также rejected на допустимых стадиях; закрытые обращения можно вернуть в triaged. Недопустимые переходы запрещены сервером.
- [x] Журнал статусов (предыдущий/следующий/автор/время), общий аудит перечня изменённых полей без значений. Историю и обращения нельзя удалить из админки.
- [x] Завершение/отклонение отмечается resolved_at, сбрасывается при возврате в работу.
- [x] Полностью отключён публичный приём: ни одного маршрута POST для заявителей, ни рассылок, ни сохранения персональных/контактных данных. Создание демо-карточки запрещено в production.
- [x] Приватные обращения никогда не выходят в статический JSON, Next.js и sitemap, что проверено тестами.
- [x] Опциональный и идемпотентный DemoMuseumRequestsSeeder для локального окружения, запрещён в production.

## Правила статусов

Новый → Принято в работу → В обработке → Выполнено. Отклонение возможно на этапах Новый, Принято в работу и В обработке. Выполненное или отклонённое обращение можно повторно принять в работу, но не перескочить сразу к завершению.

## Демонстрация на Mac mini

    cd /Volumes/ArvectumSSD/Arvectum/repos/musbread/apps/cms
    php artisan migrate
    php artisan db:seed --class=ReferenceMuseumSectionsSeeder
    php artisan db:seed --class=DemoMuseumRequestsSeeder
    php artisan test --filter MuseumRequestWorkflowTest

В закрытой админке /admin выбрать «Обращения (демо)». В локальной базе имеются две синтетические карточки: тема доступности и условная экскурсия на 20.11.2026 для 12 участников. История обработки доступна администратору в «История обращений». Для назначения редактора сначала разрешить сотруднику раздел через «Структура сайта», затем выбрать его ответственным за конкретное обращение.

## Что не готово (зависит от музея)

- [ ] Настоящая форма обратной связи и экскурсионной заявки: согласованные поля, защита и маршруты приёма, API расписаний/билетов, проверка согласий и уведомления заявителей.
- [ ] Правовая модель ПДн: оператор, основания, действующие документы, сроки хранения/удаления, шифрование чувствительных данных в закрытом сегменте, процедура ответов/выгрузки; применимость 59-ФЗ и юридический регламент регистрации и сроков.
- [ ] Распределение по ответственным автоматически, сервисные сроки, ожидание ответа, доставка уведомлений, отчёты и эскалации.
- [ ] Реальная интеграция с билетным провайдером, правила отмены/возвратов и ограничения числа мест/слотов.
- [ ] Проверка ролей и полномочий сотрудников заказчика, ACL будущих media/request ресурсов, официальный UAT.
- [ ] Промышленная защита, мониторинг, аварийное восстановление и end-to-end на двух контурах.
- [ ] Правила удаления/архивирования обращений после согласования. В демо физическое удаление заблокировано.
