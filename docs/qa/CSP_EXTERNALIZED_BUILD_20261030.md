# 30.10.2026 — закрытие проблемы CSP и дополнительных JS-запросов

**Только Mac mini и исходники; ВМ заказчика не тронуты. Это не договорная приёмка или подтверждение скорости менее 3 с.**

## Реализовано в коде

Ранее Next.js static export содержал сотни inline-скриптов React Flight. Единая политика CSP перечисляла хеши скриптов **со всех страниц** и достигала **227 089 байт** — слишком много для HTTP-заголовка.

Теперь штатный postbuild автоматически вызывает `scripts/externalize_inline_scripts.py`.

- Исполняемые inline-скрипты переведены в immutable JS-файлы `_next/static/musbread-inline/<SHA256>.js`; для каждого тега проверяется SRI `sha384-...` и `crossorigin="anonymous"`.
- Только **соседние** вызовы `self.__next_f.push(...)` объединяются без изменения порядка вызовов или расположения по отношению к другим элементам. Bootstrap и прочие JS не переставляются; JSON-LD не меняется.
- Манифест сверяет SHA256/SRI файлов с HTML, количество ссылок, отсутствие встроенного исполняемого JS и посторонних ассетов. Сломанная или смешанная сборка отклоняется.
- CSP осталась строгой: `script-src 'self'`, `script-src-attr 'none'`, без `unsafe-inline` и `unsafe-eval` для JavaScript. Отдельно остаётся прежнее разрешение для inline CSS.
- Оригинальные 27 архивных страниц новостей возвращаются из закрытого архива после postbuild; их отсутствие или повреждение блокируют релиз.
- `build_complete_museum_static_release.py` и `preflight_museum_release.py` дополнительно проверяют SRI и короткую CSP перед релизом.

Все 830 JS-файлов вместе содержат **примерно 17,7 МиБ текстовых React Flight данных для множества страниц**, а не единую загрузку посетителя. Проверка TZ-242 разделяет прежний бюджет **≤2 МиБ исполняемой логики приложения** (сейчас 930 883 байт) и новый бюджет **≤768 КиБ содержимого на одну страницу** (максимум 595 513 байт). Лимит 512 КиБ для отдельного программного JS-чанка сохранён. Передача nginx gzip может быть меньше исходных размеров, но реальное сетевое время **не измерено на сервере заказчика**.
