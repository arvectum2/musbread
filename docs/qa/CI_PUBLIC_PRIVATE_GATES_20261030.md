# 30.10.2026 — CI с явным разделением публичных и закрытых исходников

## Почему CI на коммите 4550749 не был зелёным

- Job `publisher` запускал 99 Python-модулей как будто на GitHub runner уже лежат закрытая `.local_archive` и собранный пакет из 101 подлинного PDF/DOCX, 259 адресов фотографий, 27 страниц исторической пагинации. Эти оригиналы НЕ входят и не должны входить в публичный Git. В результате — множественные `FileNotFoundError`, ложные побочные ошибки и сотни subtest failures.
- Job `web` выполнял 4 браузерных проверки PDF/документов/пагинации, физически отсутствующих в простом `npm run build`, и 2 полных многотысячных browser-census по 945 HTML с тайм-аутами 150/180 секунд. Дополнительно два теста iPhone/WebKit не могли запуститься: в CI устанавливали только Chromium.

## Исправление без поддельных документов и без объявления приёмки

1. `scripts/run_ci_python_tests.py`: GitHub использует `--profile public` (сейчас 79 source modules + новый регрессионный тест, в сумме 80), **20** явно поименованных архивно-зависимых модулей запускаются при `--profile archive` или `--profile all` на Mac mini. Все новые тестовые модули по умолчанию входят в public-профиль. Отсутствие поименованного приватного модуля — ошибка. Проверка дизъюнктности есть в `tests/test_ci_profiles.py`. Нет `unittest.skip` на уровне локального полного набора.
2. Для CI `MUSBREAD_CI_PUBLIC_FIXTURES=1` четыре конкретных Playwright-кейса, требующих приватного архивного `out`, видны как **skipped**, но выполняются в обычном локальном режиме из полной сборки. Остальные кейсы исходных страниц продолжают запускаться.
3. Два browser-census в CI проверяют детерминированную выборку маршрутов из **всех** собранных страниц при прежних разрешениях 320/390/768/1024/1440; полный браузерный обход остаётся локальным при отсутствии переменной. В CI Python `audit_structural_tz.py` по-прежнему проверяет **каждый** экспортированный HTML на header/main/footer/breadcrumbs и контакты. Эти проверки не эквивалентны полному UX/UAT.
4. В GitHub устанавливаются **Chromium и WebKit**. Воспроизводимо закреплены `lxml==6.1.3` плюс прежние проектные зависимости; SBOM обновлён до 560 компонентов, реестр прав — до 3 Python-инструментов, шесть юридических блокеров **не** объявлены устранёнными.

## Обязательные границы заявления в письме

Можно подтвердить **выбранную архитектуру, её соответствие организационной двухконтурной схеме ТЗ, реализацию и изолированные локальные испытания**. Нельзя утверждать фактические 99% uptime, ≤60 минут, ≤3 секунды, penetration test, доступность реальных пользователей, эксплуатационную готовность серверов музея, полноценный сбор/обработку ПДн и утверждение финального результата без инфраструктуры заказчика и актов. Работа CI на исходном коде — самостоятельное свидетельство, а не приёмка стадии заказчиком.

Отдельный критерий снятия красного CI: **новый GitHub Actions run на новом commit — 7/7 зелёных jobs**. До этого момента запись остаётся диагностической и не содержит утверждения CI PASS.

## 30.10 — дополнительная чистая проверка Git-only сборки

После первого коммита CI оставался занят длительными браузерными тестами. Независимо выполнен воспроизводимый Git-only `npm ci && npm run build` на чистом worktree без приватного архива музея. Обнаружены **три ранее скрытых дефекта заключительных CI-gates**; исправления приняты только после проверки реального сборочного артефакта:

1. `postbuild` теперь **до выпуска** проверяет и удаляет 88 временных `.musbread-legacy-alias`. Ожидаемые 88 исторических noindex HTML не удаляются и проверяются против фиксированной CSV-карты; любое новое/подменённое/недостающее служебное имя или изменённые байты HTML — отказ. Прежде эти служебные файлы исключались только при дополнительном приватном `build_complete_museum_static_release.py --build`, но попадали в обычный CI `npm run build`.
2. Аудит статических ссылок в **Git-only CI** учитывает 6 ссылок на подлинные документы, не поставляемые в Git, **только если** их URL и SHA-256/размер/формат присутствуют в полном закреплённом реестре всех 101 PDF/DOCX. Неизвестные отсутствующие файлы, битые ссылки, непригодный реестр и неправильные anchors по-прежнему приводят к отказу. На Mac mini в полном выпуске все реальные файлы физически проверяются и режим этой уступки не используется.
3. Структурный аудит различает 828 полноценных HTML-страниц сайта, 88 строго проверенных перенаправляющих noindex HTML и одно штатное непереведённое EN-ответвление Next.js 404/noindex. 88 служебных fallback не объявляются страницами с навигацией/футером, но строго проверяются по исходнику. Для skip link 88 fallback добавлен обязательный `title`, поэтому аудит атрибутов ссылок не ослаблен.

**Получено на чистом checkout:** `npm run build` PASS, `check_preaward_seo` PASS, `audit_public_artifacts` **6217 файлов PASS**, `audit_static_navigation` **133361 внутренних переход и 6 явно заявленных приватных документов PASS**, `audit_structural_tz` **917 index HTML / 828 страниц сайта / 88 fallback / EN 404 PASS**, `audit_link_titles` **144875 ссылок / 0 без title PASS**, локальная имитация `release_site.py deploy/verify` PASS и `audit_built_artifacts --mode web` PASS.

**В полном приватном Mac mini выпуске**, повторно собранном после этих изменений: 101 PDF/DOCX, 259 URL фото, 27 архивных индексов, 280 публикаций, контроль 150847 локальных ссылок и SRI/CSP — PASS; `audit_structural_tz` PASS и `audit_link_titles` **945 HTML / 146279 ссылок / 0 без title** PASS; весь Python профиль `--profile all` **430/430 PASS**. 12-месячная гарантия и промышленная приёмка остаются будущими обязательствами.

**Важная граница:** полные исходники и реальные измерения на ВМ музея по-прежнему не доступны GitHub CI; прохождение публичного CI не должно интерпретироваться как подтверждение этих обязательств. Полный статус GitHub Actions после публикации этого исправления нужно записывать отдельно по фактически завершённому run.
