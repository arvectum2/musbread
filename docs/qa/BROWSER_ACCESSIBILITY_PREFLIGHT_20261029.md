# QA · Браузеры, доступность, границы локального тестирования

29.10.2026. Подготовительная матрица, **не подтверждение приёмки**.

| Платформа | Браузер/версии | Проверки |
|---|---|---|
| Windows | Chrome, Firefox, Edge, Yandex — две последние поддерживаемые версии | Клавиатура, zoom 200%, 3 ширины, формы, документы |
| macOS | Safari, Chrome, Firefox — две последние поддерживаемые версии | VoiceOver, клавиатура, zoom, контраст |
| iOS | Safari на согласованных версиях ОС | Touch, VoiceOver, 320/390 px, масштаб |
| Android | Chrome на согласованных версиях ОС | TalkBack, touch, масштаб, формы |

На каждый прогон фиксировать точный номер версии ОС/браузера, устройство, дату, URL/commit, разрешение, результат, дефект и доказательство. Без реальных Windows/Android нельзя писать «PASS».

Сценарии: структура меню, skip-link, alt, ARIA, видимый фокус, контраст, реальный режим слабовидящих, отсутствие горизонтального скролла, динамический статус/ошибки, доступные альтернативы PDF, поиск, билеты, HTTPS-запрос на экскурсию и отказ сети/503 без ложного 202.

**Автоматизированные проверки:** unittest two-vm, php ingress, Laravel import, TypeScript/ESLint, Nginx и dedicated PHP-FPM syntax Docker. Последний полный Python-suite (333 теста) завершился с 103 failures/32 errors, в числе причин отсутствующие локальные оригинальные PDF и модуль xlrd. Результат НЕ считать PASS; нужен подготовленный fixture/environment и повторный прогон. Локальные тесты не заменяют pentest, нагрузку и UAT на двух ВМ музея.

**Локальный browser smoke 29.10:** Chromium — 4/4 PASS (существующие mailto формы и безопасный JavaScript-off), Playwright WebKit — 5/5 PASS (формы и 404/a11y). Это проверки локальной статики, а не нативная сертификация Safari, Edge, Яндекс.Браузера, устройств и не live HTTP-заявки.
