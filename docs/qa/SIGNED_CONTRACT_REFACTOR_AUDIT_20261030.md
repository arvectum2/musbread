# Аудит и первый рефакторинг MusBread по подписанному договору и приложениям

**30.10.2026.** Проверка по фактическому подписанному комплекту, а не только по техническому приложению из закупки.
**Промышленная приёмка: NO-GO.** Основная договорная карта: `specs/002-signed-contract/source-audit.md` (124 пункта, 1522 строк, 29 страниц, 325 TZ-ID).

## 1. Юридически обязательный комплект и условия

- Главный PDF контракта, ООЗ, передаточная форма исключительных прав и расчёт цены присутствуют в едином архиве ЕИС с отображением дат ЭП 21/23.10.2026. Detached .sig хранятся отдельно, независимая проверка цепочки криптографического доверия **не проводилась**.
- Конкурсный `Приложение_3_Описание_объекта_закупки_сайт.docx` на MacBook и приватный ЕИС `tz.docx` полностью идентичны (SHA256 `3e029344d179742632d519d4e425e6f8e9f757ce4df23e0419aa4302d4068536`). Безопасная копия публичного ООЗ в `docs/contract/OOZ_EIS_0372200172326000015.docx`.
- Текст подписанного приложения OOЗ сопоставлен с конкурсным источником по последовательности слов (4867/4884, ≈99.65%); три заголовка таблицы проверены вручную. Оставшиеся несовпадения относятся к разнице текстового извлечения, табличной вёрстке, нумерации страниц и подписанию. Для спорного положения первичен визуальный текст подписанного PDF.
- Контракт `1.4`: услуги **по 07.12.2026 включительно**. `5.1`: документ о приёмке в ЕИС в течение **трёх рабочих дней** после окончания услуг. `5.4`: применимый срок действий заказчика — **20 рабочих дней** с поступления документа. Их нельзя смешивать с внутренними сроками разработки.
- Приложение №2: **24 050,52 ₽ разработка сайта + 14 949,48 ₽ фирменный стиль = 39 000,00 ₽**. Новые платные обязательства заказчика не выводятся из нашего инженерного удобства.
- ``2.4.10–2.4.15, 6`: проверка прав на элементы дизайна, шрифты, исходники, стороннее ПО, документальная передача исключительных прав. Полный набор актов и прав ещё не согласован.

## 2. Полнота сквозной трассировки

- Все **1522 строки** подписанного PDF индексируются по физической странице и строке, SHA256 и принадлежности к контракту/приложениям.
- Выделены **124 пункта основного договора**, каждый включён в `specs/002-signed-contract/contract-clause-checklist.md` по страницам/строкам и типу требуемой проверки; правовые и процессные положения сохраняются как обязательства сторон, а не превращаются автоматически в требования к кнопкам сайта.
- Все **325 производных атомов ООЗ** связаны со строками именно подписанного PDF (322 последовательным выравниванием, 3 ручным сверенным отображением заголовков). Подлинность фрагмента и правильность инженерного толкования — разные проверочные процедуры.
- Исходный DOCX передан в Git; подписанный PDF, банковские данные и файлы электронной подписи — только в закрытом архиве на Mac mini.
- CI `--check` не может проверить невыложенный PDF и честно ограничен сверкой публичного хеш-реестра. Полный `--verify-source` запускается на Mac mini.

## 4. Незакрытые блокеры и юридические риски

1. **Промышленный инфраструктурный контур (P0):** реальная закрытая ВМ Laravel/MoonShine/БД с фиксированными доверенными IP, отдельная публичная статическая ВМ, выделенный внутренний канал, Nginx reverse proxy только в допустимом ограниченном назначении. Требуются реальные отрицательные сетевые тесты, сертификаты, пентест, backup/restore, нагрузка и демонстрация ≤60 мин после редакторского одобрения.
2. **Формы и персональные данные (P0):** безопасный приём в закрытом контуре существует в коде, публичные POST пока выключены, `mailto` не равен интегрированной системе обработки/модерации заявок. Требуется регламент обработки, ответственные лица, настройки, реальный UAT.
3. **Права и лицензии (P0):** предыдущий аудит зависимостей `LEGAL_APPROVAL=False`, шесть остаточных блокеров юридической проверки. Документированная лицензия Jodit не подтверждает права на все остальные бинарные ресурсы.
4. **CSP для крупного статического корпуса (P0):** текущий генератор агрегирует хеши inline-скриптов со всех 917 HTML-страниц в **один общий HTTP-заголовок ~226 549 байт**. Локальная генерация успешна, но это не доказательство совместимости с браузерами и сетевыми лимитами. **Не принимать как production-ready.** Перед выпуском нужен отдельный безопасный дизайн CSP с ограниченным размером заголовка и браузерной приёмкой; отключение CSP/добавление unsafe-inline для JS не допускается.
5. **Согласования музея (P0):** обязательное интервью, три оригинальные бренд-концепции по установленной процедуре, утверждение одной концепции, брендбук и исходники, редактирование/обучение, передача прав, документы нагрузочного теста и итоговая приёмка ещё открыты.
6. **Общий CI (P0):** часть предыдущих падений была вызвана устаревшими контрактами тестов и неверными путями. Исправления проверены локально; **полный новый CI** необходимо увидеть по окончании всех job. Полный Python/source-archive тестовый набор ранее имел ошибки из-за не предоставленных в Git оригинальных архивов и не считается green по отдельному Spec Kit.
7. **Подписи (юридический гейт):** даты, сертификаты и содержание подписанного EIS PDF доступны, но проверка detached .sig российским криптопровайдером/ЕИС для юридического удостоверения не выполнена.

## 5. Рекомендуемый следующий порядок по договору

Сначала закрывать ошибки CI, которые действительно относятся к результату услуг, и P0 релизной инфраструктуры; затем действовать по срокам согласований, интервью 06.11 и сроку работ 07.12. Не переписывать музейные юридические документы по памяти, не добавлять третий сервер и не приписывать статус «выполнено» пунктам, для которых не было реальных доказательств. Операционный светофор остаётся **85 / 118 / 122** до адресного подтверждения.

из-за которых shell обращался к `/dev/nulln` и получал `test: too many arguments`. Строки исправлены с отдельным тестом,
в **GitHub run 40965340470 новая проверка Infrastructure templates and Nginx parser завершилась SUCCESS**, без ослабления негативных HTTP-проверок.

оригинальности, лицензионных прав или хешей. Разделить публичную и закрытую приёмку без маскировки последней.
