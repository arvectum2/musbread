## Найденный и исправленный дефект

Строгая предпубликационная проверка существовала при ручном вызове, но **автоматические сценарии её обходили**:
- основной по умолчанию почасовой Schedule запускал museum:export без --preflight-strict;
- опциональная queued job PublishMuseumSnapshot также не передавала флаг.

Теперь ОБА автоматических режима вызывают штатный экспорт с --preflight-strict. Сохранён ручной нестрогий диагностический экспорт. Критические ошибки HTML-ссылок, материалов и событий прерывают работу до перезаписи снимка/манифеста/публикуемых ассетов. В журнале failed записывается только класс исключения, без пользовательского текста и приватных путей.

## Проверки

Новый PHP feature regression создаёт опубликованную новость со ссылкой на отсутствующий публичный URL. Перед запуском помещает контрольный старый JSON и manifest. Вызов фоновой job отказывается экспортировать, сохраняет файлы байт-в-байт, не создаёт media, выставляет failed, увеличивает attempts и оставляет snapshot_sha256 пустым. Затем тест исправляет HTML новости; новая попытка той же задачи проходит и манифест совпадает с фактическим SHA-256. Проверка расписания убеждается в почасовом запуске со строгим флагом и withoutOverlapping; действующие idempotency/ACL/ошибки остаются в тестах.
