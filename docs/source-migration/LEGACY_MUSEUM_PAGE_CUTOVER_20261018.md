# Сохранение музейных URL после переключения домена: готовая карта маршрутов

**18.10.2026.** Подготовлено 239 статических обратных совместимых адресов действующего музея. [Полный CSV с точными целями](LEGACY_MUSEUM_PAGE_ALIASES_20261018.csv). Данный режим нужен, чтобы музейное меню, старые ссылки на новости и карточки экспозиции продолжали работать после перевода `muzei-xleb.ru` на Next.js.

- 130 настоящих адресов `/novosty/YYYY-MM-DD/...` направляются на **соответствующую самостоятельную страницу** `/news/museum-news-.../`; не на абстрактный индекс новостей.
- 32 адреса реальных выставок, 17 экскурсий, 12 мастер-классов, 11 залов — на существующие каталожные страницы **с точным якорем оригинального объекта**, не на произвольные несуществующие разделы.
- 33 уникальных оригинальных адреса музейного меню и прочие проверенные разделы — на существующие общие разделы сайта; повторяющиеся исходные адреса меню имеют один предсказуемый пункт назначения.
- Каждый `npm run build` запускает `postbuild`, который генерирует миниатюрные HTML-переходники `/old-path/index.html` непосредственно в статическую поставку `apps/web/out/` и проверяет существование целевых файлов **и якорей**.
- В статическом сборочном тесте: **239/239 целей существуют, 0 недостающих, 0 коллизий/петель**. В браузере проверены реальные старые адреса статьи 2025 года, страницы выставки, истории здания и раздела доступной среды, включая проверку конкретной карточки.

**Важно про тип редиректа:** текущие переходники — браузерные `<meta http-equiv="refresh">`, то есть они работают и на простом файловом сервере. Они **не дают настоящий HTTP 301**. При размещении на выбранном продакшн-сервере нужно использовать CSV как точную спецификацию для HTTP 301/308 или штатных правил переадресации хостинга. Не использовать автоматическое правило «старый `muzei-xleb.ru` → `muzei-xleb.ru`»: оно создаст петлю.

**Важно про старые абсолютные адреса изображений:** 222 музе́йных фото-URL уже сопоставлены с **218 WebP-файлами нового сайта** (`/media/museum-source/...`). Наш сайт не загружает фото с прежнего Drupal. Однако внешние сохранённые кем-то URL `/sites/default/files/...jpg` после переключения DNS также требуют серверного правила переадресации или физической копии файлов по старому пути. Данный отчёт подтверждает автономность **страниц сайта и их внутренних фотозагрузок**, а не бесконечную обратную совместимость всех URL из интернета.

Существующие настоящие PDF/DOCX на старом сервере и внешние адреса файлов необходимо отдельно проверить при итоговой сборке. Не повторять OCR: байтовые оригиналы уже скачаны. Фактическую настройку боевого HTTP-сервера нельзя считать выполненной до выбора хостинга и подписания договора.
