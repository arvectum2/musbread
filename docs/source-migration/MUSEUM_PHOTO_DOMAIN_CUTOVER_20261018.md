# Музей хлеба: независимые изображения перед переводом домена

**18 октября 2026. Реализовано, проверено на Mac mini.** Исходный музейный сайт — `https://muzei-xleb.ru`; новый сайт — статическая сборка Next.js (`output: "export"`). Простое отображение снимков через `src="https://muzei-xleb.ru/sites/default/files/…"` было **ошибкой при будущем переводе DNS**: после переключения домена это будет адрес нового сервера, где Drupal-папки нет. Сам по себе такой запрос не образует цикл, но вернёт 404 (или начнёт циклически перенаправляться при ошибке сервера).

## Исправление

- **233 достоверных исходных URL изображений**, **229 уникальных файлов**, все скачаны через настроенную сеть Mac mini и проверены по SHA-256 и исходной музейной HTML-странице.
- Изображения экспортируются в **настоящие статические WebP-файлы самого сайта** `apps/web/public/media/museum-source/<SHA-256 исходного файла>.webp`. Не обрезаются, соблюдают оригинальные пропорции; максимальная сторона **1920 пикселей**. Полные неизменённые музейные оригиналы остаются на ArvectumSSD.
- Общий вес веб-фототеки **около 32,19 МиБ**. Эти файлы вместе с сайтом попадают в `apps/web/out/media/museum-source/`, входят в GitHub/GitVerse и в пакет следующего статического развёртывания. Зависимости от старого Drupal для изображений **нет**.
- [Таблица соответствий](../../apps/web/src/data/official-museum-photo-assets.json) содержит прежний музейный URL и страницу-источник, оригинальный SHA-256, локальный адрес WebP, контрольную сумму производного файла, размеры и объём. Это **метаданные происхождения**, а не внешние загрузки.
- Функция `localMuseumPhoto()` переписывает и `https`, и древние `http` ссылки, а также Drupal thumbnails с `/styles/foto/public/` и параметрами `?itok`. Она используется для галерей **и для старых ссылок JPG внутри исходного HTML (`RichText`)**.
- Покрытие: 85 фото 11 залов экспозиции, 15 иллюстраций истории здания, 4 фото обзорной экскурсии, выставочные обложки, экскурсии, мастер-классы, 30 новостных объявлений в виде плакатов и **семь оригинальных фото раздела доступности / МГН**. Никаких новых вымышленных изображений.
- Никакого live-запроса на `muzei-xleb.ru` при **отображении фотографий** нет. Исходные библиографические ссылки на **страницы** музея уже сопоставлены с [279 существующими маршрутами нового сайта](LEGACY_MUSEUM_PAGE_CUTOVER_20261018.md) и проверены в локальном браузере. Для боевого HTTP 301 подготовлена отдельная конфигурация, а не перенаправление старого домена на самого себя. Другие адреса вне проверенного корпуса остаются предметом дальнейшего аудита.

## Как восстановить медиатеку из источников

На Mac mini, из корня `musbread`, если меняется корпус оригиналов:

```bash
.venv/bin/python scripts/cache_official_museum_photos.py --limit 208 --delay 10
cd apps/cms && php artisan museum:import-official-photos --apply && cd ../..
.venv/bin/python scripts/export_official_museum_static_photos.py
.venv/bin/python scripts/export_official_museum_static_photos.py --verify-only
cd apps/web && npm run build
```

Команды выполняются локально на ArvectumSSD. Не импортировать сырые JPEG/SQLite в git; в git попадают только оптимизированные веб-файлы и их публичный перечень. Для нового развёртывания нельзя забывать включить в публикацию **всё содержимое** `apps/web/out`, включая `/media/museum-source/`. Веб-сервер обязан отдавать `.webp` как `image/webp`.

## Проверка перед релизом

1. `python -m unittest discover -s tests -p test_museum_self_hosted_static_photos.py` — соответствие SHA исходников и 229 опубликованных производных файлов, существование адресов.
2. Playwright `museum-self-hosted-photo-cutover.spec.ts` — локальный сервер отдаёт байты WebP (`200`, `Content-Type: image/webp`); старый музейный хост блокируется, фотографии продолжают загружаться.
3. Полный профильный E2E — экспозиция, выставки, новостные плакаты, экскурсии, мастер-классы, история здания, МГН. Статический экспорт содержит все 229 WebP.

**Результат для DNS-переезда:** старые URL фотографий не используются как `img src`/ссылки в галереях или в уже перенесённых музейных текстах. Новые изображения являются самостоятельными файлами сайта по постоянным относительным путям.

**Дополнение:** 279 действительных адресов страниц бывшего Drupal получили переходники в статической сборке. [Подробный реестр](LEGACY_MUSEUM_PAGE_CUTOVER_20261018.md). Для **чужих внешних закладок на старые JPG** серверные переадресации надо настроить при развёртывании (наши страницы уже не зависят от старых путей).
