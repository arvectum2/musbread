# Spec Kit / MusBread — практический регламент

Все команды выполнять в корне `musbread` на **Mac mini через ARC**.

## Прежде чем интерпретировать пункт

1. `python3 scripts/check_speckit_tz.py --show TZ-104` — выводит **полные исходные строки** конкретного требования, пункт, SHA источника, отдельно инженерный summary и текущий статус. Для любой другой задачи подставить её TZ-ID.
2. `python3 scripts/check_speckit_tz.py --verify-source` — проверяет весь индекс 325 ID относительно закрытых оригиналов TXT+DOCX, в том числе физическую нумерацию 485 строк, SHA и точные цитаты. Дополнительно проверяются привязки разделов всех 325 строк (в том числе составные ссылки) и совпадение 263 содержательных строк с оригинальным DOCX.
3. Открыть `spec.md` — требования и цитаты; `interpretation-review.md` — уже известные расхождения; `docs/tz-audit/requirements.psv` — реальные статусы, а не норма.
4. Перед кодом: указать оригинал и **полное** предложение ТЗ, инженерное решение, критерий теста и отдельный критерий договорной приёмки. Если формулировка двусмысленна, не выбирать удобную трактовку молча.

## Изменения и проверки

- Новая bounded-функция: отдельные `spec.md` / `plan.md` / `tasks.md` с входными TZ-ID и ссылкой на эту исходную карту. Не заменять `docs/ROADMAP.md`.
- Изменение **только статуса** после действительного прогресса: обновить `requirements.psv` с доказательством → перегенерировать зависящие матрицы → `python3 scripts/check_speckit_tz.py --render` → `--check` → `--verify-source`. Не закрывать пункт по одному зелёному тесту.
- Изменение инженерной формулировки или ссылки на оригинал: требует отдельной человеческой проверки первичного DOCX/подписанного приложения. `source-map.json` и его контрольная сумма специально защищены от тихого редактирования; `--bootstrap` повторно выполнять нельзя.
- Локальная проверка Spec Kit по официальному шаблону:
  `SPECIFY_FEATURE_DIRECTORY=specs/001-contract-tz-traceability SPECIFY_FEATURE_NO_PERSIST=1 bash .specify/scripts/bash/check-prerequisites.sh --require-spec --require-tasks --json`
- Автоматические тесты: `python3 -m unittest tests/test_speckit_tz.py -v`; GitHub Actions отдельным job запускает `--check` и эти же тесты, но не имеет доступа к оригинальным приватным файлам.

## Стоп-факторы

Не распространять оригиналы TXT/DOCX, подписанное приложение, приватные письма и ПДн через публичный Git. Отдельно проверить, совпадает ли **подписанное** приложение с EIS-оригиналом. Не выдавать Spec Kit за изменение срока 07.12.2026, согласование архитектуры, запуск сервера или приёмку.
