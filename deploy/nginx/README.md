# Перевод старого домена музея: точные HTTP 301 без петель

Эта папка содержит **готовую, но не установленную** конфигурацию для Nginx. Настоящую площадку и DNS ещё не выбирали. Не применять файлы, пока заказчик не утвердил развёртывание.

- `legacy_museum_redirects.map.conf` — автогенерируемая карта `$uri → локальная цель`, только исходные проверенные адреса музея и действительные собственные WebP.
- `legacy_museum_redirects.server.conf` — собственно `return 301` для совпавших путей. Цель всегда **относительная**, без повторного редиректа на старый `muzei-xleb.ru`.
- Генерация: `python3 scripts/build_museum_nginx_legacy_redirects.py` из корня репозитория после переноса новостей и фотографий. Тест: `.venv/bin/python -m unittest discover -s tests -p test_museum_nginx_legacy_redirects.py`.

## Включение после заключения договора

Концепция конфигурации на боевом сервере (не активировать без адаптации путей и проверки конфигурации):

```nginx
http {
    include /etc/nginx/musbread/legacy_museum_redirects.map.conf;
    server {
        listen 443 ssl;
        server_name muzei-xleb.ru www.muzei-xleb.ru;
        # Реальные certificate/key, static root, права, security headers и HTTPS
        # согласовываются по инфраструктуре заказчика.
        root /srv/musbread/out;
        include /etc/nginx/musbread/legacy_museum_redirects.server.conf;
        location / { try_files $uri/index.html $uri $uri/ =404; }
    }
}
```

Нужно отдельно проверить, что на сервер загружен **весь** `apps/web/out` с `/media/museum-source/` и HTML-страницами. Запускать `nginx -t`, затем фактический браузерный smoke-test `old HTTP URL → 301 → correct new document/WebP` на утверждённом сервере. **Нельзя** поставить переадресацию домена на этот же домен без изменения пути. На статическом прототипе, где нет управляемого Nginx, сохраняются отдельные HTML-переходники (`postbuild`), а не HTTP 301.

Охват ограничен *проверенными* URL. Другие древние адреса и PDF могут потребовать дополнительных правил после сверки первоисточника. Карта не осуществляет сбор или перенос дополнительных файлов.

**18.10.2026 — ТЕКУЩАЯ SOURCE-FIRST КОНФИГУРАЦИЯ (всё ещё НЕ развернута):** Всего **879 предложенных HTTP 301**: **280 технических адресов `/news/museum-news-…/` → проверенные первоначальные `/novosty/YYYY-MM-DD/slug`**, **60 исходных `/node/N` → человекочитаемые старые URL настоящих выставок**, **77 остальных прежних страниц/разделов** и **462 исходных пути JPG/Drupal-превью → WebP**. Все **280 исходных адресов новостей и 76 старых адресов выставок уже возвращают собственные полноценные HTML по статусу 200 в локальной сборке** — **НЕ переадресовывать их** на технические страницы или якоря. Один `/node/462` не включён: у самого музея он ведёт к закрытой HTTP 403 афише.

Перед выпуском обязательно устранить оставшиеся **137 meta-refresh переходов**, в том числе 40 технических ссылок на якоря — [автоматический SEO-аудит](../../docs/seo/CP_SEO_01_FIRST_POST_MIGRATION_AUDIT_20261018.md). Для исходных URL музея без завершающего `/` важен **200 на том же path без лишнего 301 на добавление слеша**. Предложение `try_files $uri/index.html $uri $uri/ =404` нужно протестировать настоящим Nginx, вместе с `$uri`/`$request_uri`, `location` и canonical: локальная Python/Next-сборка не подтверждает боевого HTTP-поведения. Веб-сервер также должен обслуживать **57 музейных оригиналов PDF/DOCX по прежним путям** (208,07 МиБ). **DNS и реальный сервер не изменены.**
